# ADR-052 所属项目内的 PM2 登记日志

- 状态 accepted（2026-11-07，用户确认“允许读取所属项目内的登记日志”）。补充 ADR-050/ADR-051，不修改历史决策。

## 背景与决策

真实项目将 stdout 日志配置在项目 `.pm2/out.log`。PM2 正确报告运行，原读取器仅允许实例日志根，导致日志失败。用户批准在原实例受管日志根之外，额外允许读取实际 PM2 明确登记、且位于该服务所属登记项目内的精确日志文件。

项目日志须核验同一实例的唯一 PM2 应用、完整项目服务名、namespace=larness 和登记项目。仅使用 PM2 观察得到的路径，不接受客户端路径。规范路径必须在所属项目 canonical realPath 内；项目根身份变化、越界/其他项目、最终文件符号链接/非普通文件均拒绝。打开使用 O_NOFOLLOW 并复核文件身份，保留 1 MiB 尾部与秘密脱敏。PM2 身份未知/服务已删除时不能用历史项目路径授权读取，仅原实例日志根内历史读取保持。

不开放任意文件接口，不返回原始 PM2 env/dump，不修改运行服务的配置。外部 Shell 仍可能修改路径，不能宣称 OS 沙箱或全局原子隔离。此为额外的精确服务日志读取权限；替代方案是要求 Agent 迁移所有日志到实例目录，用户本次选择兼容现有项目路径。

## 同次纠错

人工控制必须以对象 body 与 csrf:true 调用现有 apiFetch，避免重复 JSON 序列化和遗漏 CSRF。增加实际 fetch 边界回归。列表提供真实 pm2Home，界面显示同实例终端查询命令；保持原私有实例，不切换默认 ~/.pm2，不迁移用户进程。无迁移/新依赖。

## 验证

真实私有 PM2 项目日志/启停/重启，以及文件边界/符号链接/秘密/身份未知反例，Web 实际 HTTP JSON 与 CSRF，UI 查询命令。仅做必要校验，G4 仍待人类。
