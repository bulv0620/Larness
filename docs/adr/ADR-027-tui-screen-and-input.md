# ADR-027：TUI 独立屏幕与单一输入所有者

- 状态：proposed
- 日期：2026-11-02
- 决策者：待人类 G-Spec-TUI 评审
- 关联：016-tui-experience；补充 ADR-023 的交互实现方式，保留受管生命周期

## 背景

追加输出无法表达页面切换；在多个提示库与原始键盘监听间并行读取 stdin 会抢输入、破坏取消与退出。完整页面还需要中文列宽、换行、resize 和异常恢复。

## 提案

1. 终端生命周期与主界面使用 Node 内置 readline.emitKeypressEvents、TTY raw mode 和受控 ANSI 独立屏幕；保留 picocolors。不引 React/Ink，不增加原生运行依赖。
2. 单一 TerminalSession 拥有 stdin 与屏幕，页面只接收键盘事件和渲染状态。启动页/初始化继续复用现有 @inquirer/prompts 时，通过受控输入流/输出区域适配串行借出表单会话；TerminalSession 仍是物理 stdin 唯一所有者，普通输入转交表单、Esc 使用取消信号。表单期间暂停菜单分发/页面重绘，结束或取消后在 finally 回收并重绘。保留该库，禁止两个循环直接消费物理 stdin。
3. 中文列宽/换行复用锁文件已有的 fast-string-width@3.0.2、fast-wrap-ansi@0.2.2；未来在 server 显式声明直接依赖，不能直接导入未声明的传递依赖。两者为 MIT、ESM、纯 JS，当前由 @inquirer/core 依赖链使用。此次只写提案，不安装或修改 lockfile。
4. 边界输入与 IPC 返回以 Zod 校验；原始外部文字先移除终端控制序列再套本机样式。输入处理和正常退出只调用已有 supervisor/IPC，不在渲染器直接管理 DB 或审批。
5. q 在概览进入默认取消的退出确认；Ctrl+C/SIGTERM/SIGHUP 保留立即进入全局清理的语义。启动前检查交互 TTY/TERM；不支持则非 0 退出且不启动子进程，不增加 headless。
6. 使用主屏幕区域的替代缓冲区，退出恢复原缓冲区/光标/raw mode，异常和重复信号共用幂等清理。SIGKILL 仍无法保证恢复。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 继续追加输出并逐页加回车 | 改动小，但旧信息堆叠与导航问题仍在，不采用 |
| 所有菜单/日志都交给现有 prompt 逐条打印 | 可复用，但日志滚动、固定布局和页面更新受限，不采用为主界面 |
| React/Ink 或大型终端框架 | 新增框架且违背冻结 TUI 栈，本批不采用 |
| 自写 Unicode 列宽/换行算法 | 易错，不采用；复用已在依赖树的专用纯 JS 工具 |

## 影响、风险与迁移

- 无 REST/WS/IPC 数据格式、数据库或配置迁移；不提升协议版本，不新增权限。
- 增加两个既有传递工具的直接依赖声明需在本 ADR 批准后进行；无版本升级，新增产物体积以 T0-1 构建实测记录，不凭包名宣称更小。
- 维护/供应链以当前锁文件版本为基线，不声称最新或长期支持；未来升级独立评审。若无法满足 Node 20.19 或宽度/输入测试，停止该选型并记录证据，不临时换库。
- 风险：输入借出未回收、raw mode 泄漏、中文错行、控制字符注入。以真实 PTY、异常/信号恢复与文本过滤测试阻止。
- 本机 IPC/OS 权限、配对/撤销审计、密钥脱敏与退出停止服务的原则保持。
