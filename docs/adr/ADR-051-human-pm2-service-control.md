# ADR-051 服务运维人工启停

- 状态 accepted（2026-11-07，用户明确要求服务运维弹窗增加人工启停，并与项目服务窗保持 UI 一致）。
- 补充 [ADR-050](ADR-050-pm2-cli-deployment.md)，不修改旧 ADR。

## 决策

服务运维继续从左侧打开，使用项目服务窗相同的卡片列表、详情、状态徽标、信息卡与日志样式。去掉可见副标题。认证人类可对准确选中的已关联 PM2 应用执行启动、停止、重启，停止与重启先确认名称和项目。关闭弹窗不影响进程。

新增人工 REST `POST /api/service-ops/services/:id/control`。人类按钮与确认构成该次明确授权，不绑定当前聊天或 Agent 审批策略。仍执行全局认证/CSRF，在实际 PM2 操作前复核活动客户端、项目归属、完整名称、namespace、项目→服务锁/fencing；以现有资源操作表记录幂等意图，完成结果、资源事件与审计事务提交。Agent 不获得新工具，继续通过通用命令控制 PM2。

仅对实例内已有且身份明确的应用操作，启动通过 PM2 恢复已有应用，保持配置和环境。缺失应用、namespace 冲突、未知状态拒绝，不从旧产物猜测配置重建。副作用后核对配置身份与真实进程状态；运行不等于健康已通过。重复成功请求不重复重启，同键异参或未完成请求拒绝。失败/中断不自动重试，租约过期的中断意图由观察流程标为失败、允许刷新状态后人工决定新操作。无迁移/新依赖。

## 边界与替代方案

继续采用旧产物授权会使 CLI 服务无法启停；伪造产物版本或哈希会掩盖授权意义，故使用单独人工接口。将按钮转成聊天指令会增加用户操作，不满足直接人工控制。外部 Shell 不遵守受管锁，PM2 名称/配置复核不构成 OS 原子隔离。控制接口不接受脚本、路径、任意参数或环境，日志依旧脱敏。

## 验收

UI 确认/取消/失败与所属项目会话、真实私有 PM2 的启停/重启/重复请求、认证/CSRF/参数/身份和项目写锁反例。必要检查与用户手动验收见 M4-R1 验收记录。
