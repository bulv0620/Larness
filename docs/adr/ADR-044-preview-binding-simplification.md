# ADR-044 服务登记不再限制绑定地址，预览按已核验本地地址拨号

- 状态：accepted；2026-11-05。人类明确要求简化：“终端运行了前端，根据终端监听端口创建可访问服务；访问不了就显示访问不了”。本 ADR 修订 ADR-043 第 5 条中“拒绝 0.0.0.0/:: 通配监听”的条款，其余身份/票据/隔离约束继续有效。
- 关联：ADR-043、[M3 技术契约](../contracts/m3-preview.md)、[040 spec](../../specs/040-services-preview/spec.md)。

## 背景
原实现要求监听地址必须是 `127.0.0.1`/`::1`，否则拒绝登记。实际开发中 Vite/框架常默认绑定 `0.0.0.0`；该监听本就可被其他设备访问，拒绝登记并不减少暴露，反而让“根据终端端口创建入口”这一简单模型无法使用，并制造了额外配置负担。

## 决策
1. 登记只要求：请求端口存在**属于该终端、独占且可核验**的监听；不再以绑定地址拒绝。`127.0.0.1`、`::1`、`0.0.0.0`、`::`、具体本机地址均可登记。
2. 登记记录内核监听表中的实际地址与拨号地址：回环/通配拨 `127.0.0.1`；具体本机地址拨该地址。地址来自 `lsof` 监听表，不接受客户端自报 URL/IP，因此不引入任意目标 SSRF。
3. 预览失败不再等价于登记失败：拨号/转发失败时服务保持已登记，预览明确显示不可用；不自动重启、改绑定或重写目标。
4. 继续保留：终端后代/launch 身份、监听 owner/birth、独占归属、endpoint generation、短期票据/grant、预览 host 隔离、管理 Cookie/API 隔离、撤销与对账。
5. UI/文档不再承诺“业务端口无需公网暴露”；预览只是给已授权用户的入口，不是服务唯一访问路径。

## 结果与边界
- `0.0.0.0` 上的前端可直接登记，预览经 `127.0.0.1` 访问。
- 仅绑定具体非回环地址的服务，预览拨该地址；若主机防火墙/路由导致连不上，预览显示不可用，登记仍保留。
- 该模型不提供“预览即隔离网络”的承诺；管理凭据隔离仍由独立来源与 grant 保证。
- 若未来需要“预览必须只经网关”的强隔离模式，应作为新的显式配置/策略评审，不默认恢复拒绝。

## 验证
- 服务端：通配监听登记成功；预览对通配服务经 `127.0.0.1` 转发。
- 既有身份/退登/票据/安全矩阵测试保持通过。
- 构建与浏览器 E2E 复跑见 M3 收尾记录。
