# ADR-071 长任务连续执行：取消任务级预算与上下文换页

- 状态：accepted（2026-11-19，人类确认按 085 默认值实施）。
- 关联：[085 spec](../specs/085-long-task-continuity/spec.md)、[ADR-057](ADR-057-runtime-efficiency.md)、[ADR-059](ADR-059-long-task-budget-and-continuation.md)。
- 取代范围：本 ADR 取代 ADR-059 中“任务级 token 上限、180 分钟 Turn 总墙钟、固定接续深度 3、80% 收尾提示”的默认行为；保留 ADR-059 的接续事件、检查点、跨切片花费统计与安全约束。

## 背景

ADR-059 以“花费为主、时长为兜底”约束长任务，解决了成本失控和固定步数截断。但当前默认值落在正常长任务的执行区间内：

- `contextWindow × 30` 对每步重发完整历史的任务只够几十个满上下文步骤；
- 180 分钟会切断正在进行的 install/build/e2e，且 `duration` 不接续；
- 接续深度 3 在任务完成前停止；
- 80% 收尾提示要求模型“停止探索并总结”；
- 无工具事实的任务在上下文触顶后不接续。

人类目标已明确：**成本不敏感，长任务完成优先；现代模型主动死循环很少，限制不应拦正常任务。** 因此需要把“任务级预算”与“操作级超时”分开。

## 决策

1. **默认关闭任务级 token 上限。** `maxTotalTokens = 0`、`spendCapContexts = 0`；显式正数仍可作为诊断/实验开关。usage 继续记录，但不作为停止条件。
2. **Turn 总墙钟改为紧急兜底。** `maxDurationMs = 24h`，`maxSteps = 1000`，`maxToolCalls = 0`；24h 同时作为整条任务链的紧急墙钟，1000 步是单 Turn 的防循环兜底。正常任务不应触发；紧急兜底只防代码 bug，不是产品预算。
3. **取消固定接续深度 3。** 接续次数由任务完成、用户取消或紧急兜底决定；保留链路遍历的防御上限。
4. **删除 80% 收尾提示。** 不再在正常进度上要求模型停止探索；只在紧急兜底或用户显式要求时提示。
5. **上下文换页是正常路径。** 当输入窗口达到 **85%** 时，保存检查点、创建带 `resumedFromTurnId` 的接续 Turn，并将原 Turn 记为 `terminalReason=continued`。正常换页不使用 `budget` 终态；输出预留仍由发送前的硬检查单独保证。
6. **无事实也能换页。** 没有工具事实时，使用最近消息与现有摘要生成承接输入，并标记为降级；不再因 `factsAreEmpty` 直接停止。
7. **保留操作级超时。** 单次模型请求沿用适配器默认上限（600s）并受剩余紧急预算约束；单条命令保持默认 300s、最大 1800s；锁等待、审批 TTL 和取消不变。操作超时只失败当前操作，结果返回模型，任务可继续。
8. **无进展检测替代总时长。** 连续 10 分钟没有模型输出、工具输出、文件变更或计划更新时，以现有 `INTERRUPTED` / 恢复入口暂停并询问用户；默认不自动杀任务。
9. **上下文阈值。** Turn 起点装配预算保持 80%；85% 换页按输入窗口计算，保证装配后的新 Turn 不会立即再次换页；摘要压缩阈值从 70% 提高到 80%；跨 Turn 历史改为按 token 预算裁剪，不再固定 40 条。
10. **`continued` 是新增终态。** `TurnTerminalReason` 增加 `continued`，表示“片段结束、任务继续”，不代表任务完成；Job 判定为未完成，UI 显示“自动继续”，接续轮合并为同一任务流。
11. **定时任务保持独立语义。** Agent Job 仍使用 `timeoutSeconds`，超时按既有语义取消，不自动做用户会话式换页。
12. **输出截断单独处理。** `maxOutputTokens` 与任务级预算分离；`output_truncated` 仍表示单条输出被截断。

## 备选方案

- **保持 ADR-059 仅调大数值**：仍是任务级上限，长任务仍会在固定点截断。
- **完全移除所有限制**：挂起命令/请求会永久占用队列；物理窗口仍会失败。
- **只做压缩、不换页**：长任务会持续丢失细节，最终仍可能触顶。
- **换页也走 `budget` 终态**：语义会继续把正常换页显示为失败/预算耗尽。

## 影响

- **产品 / UI**：长任务可能跨越多个 Turn；时间线合并显示“自动继续”，不显示“预算耗尽”；`continued` 不视为任务完成。
- **API / 契约**：`TurnTerminalReason` 增加 `continued`；`turn.continued` 事件复用；REST/WS 文档与 Job 判定同步。无数据库迁移（`terminal_reason` 是文本列）。
- **数据**：复用 `resumed_from_turn_id`、检查点与摘要表，不新增 schema。
- **安全 / 权限**：接续是完整的新 Turn，仍走当前会话的授权、项目锁、审批和审计；不提升权限。
- **成本**：默认不再用 token 上限拦截；usage/缓存统计保留用于展示与诊断。
- **风险**：异常任务可能长期占用队列；由 24h/1000 步紧急兜底、无进展暂停和用户取消共同约束。

## 验证与回滚

- 验证：`test/agent` 覆盖长任务超过旧上限、85% 换页、`continued` 终态、无事实接续、操作超时、取消、Job 超时、接续安全边界；Web 覆盖时间线合并与“自动继续”；`pnpm check` 与 `pnpm build` 通过。
- 回滚：恢复 `DEFAULT_BUDGET` 的任务级 token/时长/步数上限、`DEFAULT_MAX_CONTINUATIONS=3` 与 80% 收尾提示，并让 `onSettled` 只处理 `budget` 接续；已产生的 `continued` Turn 保留为历史，不影响回滚后的新 Turn。
