# ADR-048 会话开发服务与正式服务运维分域

- 状态：accepted（2026-11-06，用户要求从设计上分离会话服务和正式服务运维，包括 Agent 工具）。
- 关联：[ADR-030](ADR-030-resource-lifecycle-and-services.md)、[ADR-042](ADR-042-service-deploy-boundary.md)、[ADR-046](ADR-046-pm2-delivery-and-lifecycle.md)、[ADR-047](ADR-047-service-operations-entry.md)。

## 决策

| 边界 | 会话开发服务（M3） | 正式服务运维（M4） |
|---|---|---|
| 资源 | 绑定已核验的终端执行与监听端点，源退出即退登 | 从显式授权的发布计划与产物建立，PM2 独立运行，保留版本与部署历史 |
| 界面 | 聊天服务浮窗、终端及隔离预览 | 左侧「服务运维」，项目与聊天只提供可追溯的来源信息 |
| 数据与协议 | 现有 `services` 记录、`serviceId`、`/api/services`、`service.*` 和预览解析 | 独立仓储、资源身份、DTO、`/api/service-ops/` 与运维事件流。部署记录归该域 |
| Agent | 现有开发终端与临时服务工具按会话作用域装配 | 独立的运维工具组与执行上下文，按后端核验的运维授权装配 |

1. 正式服务使用独立资源 ID、仓储和后端模块。两域分别校验 ID、动作、作用域、日志和事件订阅及补拉。发布计划只能引用可核验的构建输入或产物以及正式目标。临时服务 ID、PTY、端口、预览地址和旧审批均不能转换为正式服务身份或授权。开发预览只解析临时服务。
2. 运维工具有独立名称、模型参数 schema、执行 handler、上下文说明和结果类型。普通开发 Turn 的模型上下文只提供该会话已获授权的开发能力，开发执行器也拒绝直接提交的运维工具调用。运维工具仅在后端从运维入口建立、绑定已授权项目与目标范围的上下文可用。页面位置、前端字段、模型意图和已有会话权限不能为 Turn 增加运维能力。运维上下文也不装配临时服务和预览工具。
3. 继续共用单实例 SQLite、鉴权、策略引擎、锁、审计、事件持久化及模型运行器等基础设施。每次动作仍按实际域和目标校验。运维 UI 与运维 Agent 共用一套正式后端。已授权的 autonomous 运维动作沿用 ADR-042 的免人工规则，策略不会替代运维作用域授权。

## 兼容与验收

此前的共用服务表、按 `kind` 区分查询及共用工具的 M4 草案由本 ADR 替代。保留现有开发服务接口、工具名、数据和历史结果卡。新增正式运维记录放在同一业务数据库中的独立仓储，避免改写旧记录或收养运行中的进程。正式服务运行与退出继续遵循 ADR-046。

M4-1 定义发布来源和正式目标的边界，M4-2 校验运维作用域与授权，M4-3 实施独立资源、协议及运行能力，M4-3b 接入 UI 和工具装配，M4-4 集成验收。验证两个真实模型上下文的工具列表、描述、schema 与 system prompt，并向真实执行器、REST、预览和事件重放提交跨域反例。详见 [M4 验收 D13–D16](../../specs/050-deploy/spec.md#3-验收场景)。工具的具体名称、入口交互、路由后缀、字段与事件 schema 按对应任务冻结。
