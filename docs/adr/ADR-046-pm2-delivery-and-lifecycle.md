# ADR-046 PM2 交付与正式服务退出边界

- 状态 `proposed`（2026-11-06）。
- 关联 [G-Spec-M4 评审包](../../specs/050-deploy/review.md)、[ADR-023](ADR-023-tui-as-managed-entry.md)、[ADR-042](ADR-042-service-deploy-boundary.md)、Q-003、Q-027。

## 背景

M4 需要运行正式服务。ADR-023 对受管 TUI 定义了前台入口与退出清理。正式服务的独立生命周期以及 PM2 如何交付，需要单独批准并验证。

## 候选决策

1. 以固定版本 `pm2@7.1.2` 验证随包交付，保留 `node app.js` 入口。通过同一受管适配器访问专用 `PM2_HOME`，按实例、服务登记、版本和配置核对真实目标。无关的 PM2 实例由其原操作者管理。公开分发及最终依赖版本在 PoC 后按证据和许可评审确认。 [PM2 npm 元数据](https://registry.npmjs.org/pm2/7.1.2)
2. 候选为正式服务独立于 Larness 管理进程。正常 TUI 退出时停止接收新变更，等进行中的部署到达可记录的安全点，清理管理进程及临时开发资源。已确认的正式 PM2 服务继续运行。启动后复核守护、服务、版本与健康。Larness 更新遵循安全点，触及 PM2 运行时时须先核对影响。此条如获准，将为 ADR-023 增加限于正式服务的例外。
3. 首轮使用同一 OS 账户的应用层隔离。PM2 运行目录、socket 和日志位于项目源码外，连接和动作由后端受控执行。守护不可用、身份不明或计划失效时记录异常并拒绝未经确认的变更。主机开机自启需要独立的系统配置和证据。 [PM2 多实例说明](https://pm2.keymetrics.io/docs/usage/specifics/) · [PM2 开机启动说明](https://pm2.keymetrics.io/docs/usage/startup/)

## 备选与影响

| 备选 | 影响 |
|---|---|
| 用户提供指定版本及绝对路径 | Larness 发布物更小。安装和升级由使用方负责，适配器仍校验版本与专用实例。 |
| TUI 正常退出同时停止正式服务 | 延续统一停止行为。退出会中断正式服务访问，配置与部署历史保留。 |

本提案不引入产品 API 或迁移。采用独立生命周期时，TUI 退出提示需要明确指出正式服务会继续运行。PM2 环境、日志、持久化快照及守护进程失效行为须经隔离实验验证，特别是敏感信息泄露、误接入默认实例和重复启动路径。

## 验证与回退

在临时数据目录用独立测试实例验证 [P1–P5](../../specs/050-deploy/review.md#m4-0-实验证据)。如果候选失败，保留证据并重新评审；测试清理只针对已核验的实验实例。回退不处理用户已有的 PM2 进程或数据。
