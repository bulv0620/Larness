# ADR-046 PM2 交付与正式服务退出边界

- 状态 `accepted`（2026-11-06，用户确认产品边界；安装与接入细节待 PoC）。
- 关联 [G-Spec-M4 评审包](../../specs/050-deploy/review.md)、[ADR-023](ADR-023-tui-as-managed-entry.md)、[ADR-042](ADR-042-service-deploy-boundary.md)、Q-003、Q-027。

## 背景

M4 需要运行正式服务。用户确定 PM2 全局安装、TUI 启动检查并补装，以及 Larness 管理进程异常退出时正式服务继续运行。ADR-023 对受管 TUI 定义了前台入口与退出清理。用户进一步确认，正常退出也保留正式服务，重开后可查看状态。

## 决策

1. 保留 `node app.js` 受管 TUI 入口。初始化检查当前 Node/npm 环境下的全局 PM2，复用兼容版本，缺失时按 PoC 验证的固定版本和安装参数自动安装。已装但不兼容、npm 不可用或安装失败时，候选行为为提示原因并限制正式服务管理，允许常规开发。PoC 使用独立临时 npm prefix，不改变实际全局安装。 [PM2 安装说明](https://pm2.keymetrics.io/docs/usage/quick-start/)
2. PM2 守护进程与 Larness 管理进程独立。管理进程异常退出时，已运行的正式服务继续提供访问。正常 TUI 退出时停止接收新变更，等进行中的部署到达可记录的安全点，清理管理进程及临时开发资源，保留正式服务。此项补充 ADR-023，仅为正式服务增加例外。重开后复核守护、服务身份、版本、启动配置与健康并展示实际状态，缺失或无法核验时显示实际异常或未知。Larness 更新遵循安全点，触及 PM2 运行时时须先核对影响。
3. 首轮使用同一 OS 账户的应用层隔离。每个 Larness 实例通过同一受管适配器访问私有 `PM2_HOME`，按实例、服务登记、版本和配置核对真实目标。默认 PM2 实例和其他实例由原操作者管理。PM2 运行目录、socket 和日志位于项目源码外，连接和动作由后端受控执行。守护不可用、身份不明或计划失效时记录异常并拒绝未经确认的变更。主机开机自启需要独立的系统配置和证据。 [PM2 多实例说明](https://pm2.keymetrics.io/docs/usage/specifics/) · [PM2 开机启动说明](https://pm2.keymetrics.io/docs/usage/startup/)

## 备选与影响

| 备选 | 影响 |
|---|---|
| TUI 正常退出同时停止正式服务 | 延续统一停止行为。退出会中断正式服务访问，配置与部署历史保留。 |

本提案不引入产品 API 或迁移。M4 产品实现时，TUI 退出提示需要明确指出正式服务会继续运行。PM2 环境、日志、持久化快照及守护进程失效行为须经隔离实验验证，特别是敏感信息泄露、误接入默认实例和重复启动路径。

## 验证与回退

在临时数据目录用独立测试实例验证 [P1–P5](../../specs/050-deploy/review.md#m4-0-实验证据)。如果候选失败，保留证据并重新评审；测试清理只针对已核验的实验实例。回退不处理用户已有的 PM2 进程或数据。
