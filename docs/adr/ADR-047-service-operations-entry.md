# ADR-047 正式服务的服务运维入口

- 状态：accepted（2026-11-06，用户明确将正式服务移出聊天浮窗，放在左侧「自动化任务」附近的「服务运维」）。
- 关联：[ADR-030](ADR-030-resource-lifecycle-and-services.md)、[ADR-042](ADR-042-service-deploy-boundary.md)、[ADR-046](ADR-046-pm2-delivery-and-lifecycle.md)。

## 背景与决定

开发服务绑定项目终端的某次执行，主要用于调试和隔离预览。正式服务从发布产物启动，由 PM2 托管，日常管理要能脱离当前聊天和项目选择。ADR-030 原先把两类服务安排在同一个浮窗。该展示规则由本 ADR 补充。

1. 聊天浮栏的「服务」入口、浮窗及开发预览继续展示该工作区或项目的临时服务。正式服务及其 PM2 操作从左侧与「自动化任务」同级的「服务运维」进入。
2. 「服务运维」作为独立页面，展示当前认证和授权范围内的正式服务。可查看运行状态、健康、当前版本、日志和部署记录，并按现有授权执行启停、重启及支持的恢复。来自项目的发布仍记录来源项目和产物，以供追溯及后端授权；切换聊天或项目不改变运维页的服务范围。
3. 页面使用 M4 的正式服务后端，手动操作和 Agent 共用同一套 PM2Adapter、锁、策略和审计。PM2 生命周期与重开对账遵循 ADR-046；自动化调度仍归 M5。

## 备选与影响

共用聊天浮窗会让正式服务列表依赖当前开发项目，且将预览和运维操作混在同一视图。独立入口把两种操作分开，页面访问范围继续由后端鉴权，不能从侧栏位置或当前项目推导授权。

本次变更为产品规格和验收更新。UI 接入归 M4-3b，包含两处列表按资源类型正确展示、无活动会话时可进入运维页、换项目后仍能查看同一正式服务、状态对账及操作失败可见。M4-0 的 PM2 证据及后续门禁仍适用，实施按 M4 任务顺序。

设计回退只涉及导航和查询视图，不迁移、不停止已有 PM2 进程。具体路由、DTO 和运维页面布局按 M4-3b 技术规格确定。
