# ADR-042 开发运行/正式发布边界与策略化部署授权

- 状态：accepted（2026-11-05，用户明确接受边界调整并确认“完全自主就是完全免人工”，要求更新文档）。
- 本次授权：更新设计，不代表M3/M4技术规格、G-Spec或PoC通过，不授权直接实施。

## 决策
1. M3为开发服务与隔离预览：登记终端现有监听进程、日志/状态、精确源退出退登、Browser/HTTP/WS/HMR与前后端开发访问。不负责PM2、构建产物或正式服务运行。完成M3即可使用完整开发预览，不依赖尚未发生的正式部署。
2. M4为持久运行与版本发布：PM2交付/命名空间/退出与恢复PoC、持久服务生命周期/日志/对账、构建/产物/计划、首次部署/替换/健康/版本记录和支持的失败恢复归同一阶段。只实现一套PM2Adapter、健康/日志/对账能力，由发布流程复用。旧M3-5迁入M4-0/M4-3，旧M3-5b迁入M4-3b；旧编号保留为迁移记录，不伪标完成。
3. 全部Agent业务动作共用真实策略快照。autonomous启用后，包括登记开发服务、PM2启停重启、首次部署、产物替换、发布后验证和支持的恢复，均不再有人类审批/确认步骤。不得硬编码“生产部署始终人工批准”或以风险为由在此模式中额外弹审批。启用该模式时既有风险确认仍保留。
4. 免人工不等于免授权或免计划：后端仍验证身份/范围/参数/计划及产物哈希/时效/锁fencing/幂等/预算/取消/审计/秘密/隔离。标准/严格依风险询问，只读拒绝写入；失败或未知状态拒绝执行，不按“自主”猜测成功。计划变更必须重建并重新执行策略决策，不能篡改旧计划；自主模式重决策仍无需人工。
5. 审批记录与策略授权记录区分：需要人工时才创建审批请求、WAIT_APPROVAL和approvalId；自主直接记录策略允许、planHash和policySnapshotId后执行，不制造人类批准、无审批弹窗或停等用户。运行结果/错误/审计继续可见。
6. 本规则面向已授权的Agent业务能力，不新增设备配对/凭据、本机管理或OS特权能力，不修改M2人工Git资源动作的独立授权，不改变代码/spec实施前的人类评审门禁。TUI退出对正式PM2的Q-027仍未决，移到M4前解决，不默认常驻或强杀。

## 补充关系
- 补充ADR-005：部署必须经过后端策略授权和审计，人工审批是条件分支；autonomous免人工。原“不可绕过审批”应解释为不可绕过授权决策，不能据其给自主模式加固定人工关卡。
- 补充ADR-030：临时/持久服务的进程所有者与卡片规则不变；实现阶段和持久部署的人工询问改按本文。
- 补充ADR-040：明确其免询问覆盖后续服务与部署，不只限已完成的M2工具。冻结ADR原文保留，不重写历史。

## 替代、影响与风险
保留旧划分会让M3管理已部署服务却依赖M4首次发布，并重复定义健康/PM2；合并所有里程碑会使开发预览必须等待部署完整链路。采用两个用户闭环，减少逆向依赖。自主发布可能自行替换/停止服务并产生影响，用户通过策略选择授权；执行验证、审计和支持范围不削弱。无本次运行代码/新依赖/数据迁移；草案字段/配置在后续技术评审冻结。

## 验证与回滚
文档检查M3无PM2实施依赖、M4承接完整闭环、普通/只读/自主策略场景齐备，自主无人工等待但篡改/过期/未鉴权仍拒绝。实际实现后用真实终端/代理和隔离PM2验证，不用Mock冒充通过。若调整回旧产品策略需新ADR/人类决定，本次不回滚已验收M2代码。
