# ADR-062 · 模型连接与能力目录

- 状态 `proposed`（2026-11-14）
- 关联 [077 规格](../../specs/077-model-connections/spec.md)、[ADR-053](ADR-053-model-catalog-thinking.md) 与 [工程宪法](../../CONSTITUTION.md)

## 背景

当前目录和选择器按凭据分组，模型预算、可见性和计费线路耦合。部分平台只公布模型标识，部分则给出协议能力和窗口。OpenCode Go 这类聚合服务通过自己的套餐同时提供多个厂商模型。

## 提议

1. 连接使用预设和凭据版本，UI 以模型为入口。按量、套餐和地域不同而影响调用的预设由用户明确选定。模型标识按服务端接入预设、协议及准确上游 ID 解释。
2. 目录发现、能力数据和调用验证分别建模。允许按连接覆盖具体模型字段。经校验的目录可以独立更新能力，凭据、官方端点、认证头和适配器由应用控制。
3. Turn 固定连接与凭据版本、模型、协议和预算。失败时提示修复或重选。继续在单 Turn 内存中处理私有思考回传。
4. 保持 Secret Store 和 endpoint 安全要求。目录提供者不接触 Key。已部署连接保留 ID 和端点；数据库迁移沿用备份流程。

## 备选与取舍

- 每个平台维护源代码里的静态模型表。实现直接，新模型需发布，无法充分利用上游字段。
- 全量信任模型聚合目录中的地址、SDK 与能力。更新便捷，会把凭据和请求路由交给外部数据。
- 继续按 Key 展开会话列表。便于看凭据，平台和模型数量增加后重复项会扩大。

## 影响与验证

批准后按 077 逐项替代 ADR-053 的 Key 分组 UI 与能力来源约定。验证旧数据与凭据版本、真实 Provider 工具续步、端点安全、权限与可见性、目录失败恢复和独立更新。涉及数据库回退时恢复迁移前备份及匹配的密钥材料。
