# ADR-050 Agent 通过命令行部署 PM2 服务

- 状态 accepted（2026-11-07，用户明确要求撤回专用构建和发布工具，改用命令行并提供 PM2 环境和项目关联）。
- 关联 [ADR-042](ADR-042-service-deploy-boundary.md)、[ADR-046](ADR-046-pm2-delivery-and-lifecycle.md)、[ADR-048](ADR-048-service-domain-separation.md)、[ADR-049](ADR-049-service-ops-dialog.md)。
- 实施状态见 [M4 任务](../../specs/050-deploy/tasks.md)。用户随后授权本轮同时实施命令行接入，旧 M4 后端发布接口作为兼容能力保留。

## 背景

PM2 已提供启动、停止、重启、日志和进程状态的命令行接口。Agent 已有文件、命令、终端和任务计划工具。原 M4 将构建、产物、计划和发布包装成另一套模型工具，普通会话还需要切换到独立运维入口，增加了重复的执行流程。

用户确认以通用命令行完成构建、发布和日常运维。系统负责提供准确的运行环境、服务归属和实际观察结果。

## 决策

1. Agent 在普通项目会话使用现有 `run_command` 执行构建和有限 PM2 命令，文件工具用于读取项目配置。复杂任务复用 `update_plan`。持续交互仍使用终端工具。退出后的正式进程由 PM2 守护管理。
2. 取消专用模型工具的设计，包括构建、生成发布计划、apply、正式服务列表、日志和启停工具。正式部署采用命令执行的策略授权、参数绑定、审计、幂等、超时和取消机制。系统专用不可变产物/发布计划/部署 grant 退出新的 Agent 操作主线。
3. 服务、终端和预览继续采用各自的后端资源身份。普通会话可发起正式部署，服务运维弹窗提供全局查看入口。取消以独立模型工具组和运维 Turn 作为部署的必经入口。原界面内的运维指令可转到绑定来源项目和所选服务的普通会话。
4. PM2 保持全局安装，Larness 的命令进程由后端提供已核验的 Node/PM2 入口、PATH 和 `PM2_HOME=<dataDir>/pm2`。当前方案沿用 ADR-046 的实例目录。具体路径写入每次模型请求的系统上下文，并与执行器实际使用的值一致。模型无需猜测安装位置或伪造 env 参数。PM2 通过 `PM2_HOME` 选择实例。[PM2 多实例说明](https://pm2.keymetrics.io/docs/usage/specifics/)
5. 新服务统一 `namespace="larness"`，唯一名称为 `larness:<projectId>:<serviceKey>`。`projectId` 使用登记项目的稳定 ID，`serviceKey` 采用简单名称，同一项目可有 web/api/worker 等多个服务。关联同时出现在 ecosystem 配置和后端观察结果中。项目重命名不改变关联。已提交实现的 `larness-<targetId>` 通过原目标记录恢复项目归属，作为兼容名称保留。
6. PM2 是进程状态的来源。后端从同一实例读取白名单字段，核对 namespace、唯一名称和已登记项目后持久化观察结果，再发事件并提供给运维弹窗与 Agent。`pm_id` 和 PID 可变化，关联不能以它们或当前会话为主键。归属缺失、冲突或失联时明确显示未关联或未知。`cwd` 和脚本路径只作佐证。
7. 命令返回码为 0 表示命令完成。正式服务的 PM2 状态、进程身份、实际访问和健康检查分别核对，成功声明对应真实观察。CLI 超时后先读取状态再决定重试，避免重复启动。构建前的步骤计划描述目标与影响，具体命令仍逐次按策略授权。
8. 管理数据、运行日志和发布目录在 Larness 源码外。Agent 可按项目脚本构建，并用命令准备部署目录和 ecosystem 配置。系统上下文提供本项目发布根目录。具体打包、依赖准备和恢复方案由项目与任务决定，不预设任意项目都能复制 dist 后启动。

## 权限与秘密

通用命令继续按已确认的可信开发机模式执行。服务命名用于关联识别，不能作为 OS 权限边界。项目锁只协调 Larness 的受管写作业，任意脚本和宿主机进程的能力按宪法第四条如实说明。

`run_command` 保持 `executable/args/cwd/timeoutMs` 参数，不增加模型可设置的 env 或身份字段。构建和 PM2 命令使用现有风险分类，无法可靠判定只读的命令按 L2 处理。readonly 从已核验的系统观察读取状态，拒绝命令写入。autonomous 对已授权步骤免人工确认，其他策略沿现有命令审批。PM2 的全局影响命令必须有对应用户任务授权。

后端只注入非秘密运行信息和服务摘要。PM2 完整环境、原始 `jlist`、dump、凭据及日志里的秘密不得进入模型和前端。常规状态使用系统摘要或 `pm2 list`，日志使用有限行数和 `--nostream`。正式 `secretRef` 注入继续列为 Q-029，命令行方案不允许把明文秘密写进参数或配置。

## 替代关系

- ADR-042 的阶段划分与自主策略继续生效。其正式发布的专用 planHash/artifactHash/grant 流程由本 ADR 的通用命令授权与结果核验替代。
- ADR-046 的安装、私有实例和退出边界继续生效。其必须通过唯一 PM2Adapter 发起所有写动作的条款由命令行执行和后端观察协作替代。
- ADR-048 的资源、REST、事件和预览领域边界继续生效。专用模型工具注册、禁止普通会话部署和独立运维上下文必经入口的条款由本 ADR 替代。
- ADR-049 的左侧服务运维弹窗继续作为正式服务查看入口。
- 原 ADR 文本及已完成实施记录保留为历史。原 M4 数据表、发布历史和运行中服务按迁移任务处理。

## 验收

在专用测试实例验证实际命令与模型上下文使用同一 PM2 环境，命令构建/首次运行/替换/日志/停止/重启，两个项目和同项目多服务的关联，项目重命名及旧服务兼容，退出后持久运行、重开对账、取消和重试、四策略、事件持久化及秘密脱敏。详情见 [M4 spec](../../specs/050-deploy/spec.md)。
