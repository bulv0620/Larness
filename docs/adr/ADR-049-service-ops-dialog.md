# ADR-049 服务运维改为弹窗入口

- 状态：accepted（2026-11-06，用户直接要求）
- 关联：[ADR-047](ADR-047-service-operations-entry.md)、[ADR-048](ADR-048-service-domain-separation.md)

## 背景

ADR-047 将正式服务放在左侧「服务运维」独立页面。用户在 M4-3b 手动验收前明确要求：“不要做成页面，做成弹窗，而且风格要符合目前的设计”。

## 决策

1. 保留左侧底部与「自动化任务」同级的「服务运维」入口。
2. 点击入口打开一个弹窗（Radix Dialog），不新增或跳转 `/service-ops` 路由；关闭弹窗回到原工作区，不改变当前项目/会话/窗口。
3. 弹窗沿用现有 Dialog 视觉与交互：遮罩、圆角、语义 token、标题/描述、右上关闭、滚动内容、现有卡片/状态/日志样式。大尺寸仅用于容纳列表与日志，不引入第二套 UI 框架。
4. 弹窗内仍展示正式服务列表、实际状态、版本/PID/健康、发布历史、日志、启停重启、人工审批与运维 Agent 指令；聊天浮窗仍只展示临时开发服务。
5. 数据、REST、事件和 Agent 分域不变；仅展示入口和布局变化。

## 影响与验证

- 移除 `/service-ops` 路由；`e2e-auth/service-ops.spec.ts` 改为点击左侧入口、断言弹窗可见/可关闭且 URL 不跳转。
- 组件测试使用 `ServiceOpsDialog`；现有 `Dialog`/token/状态组件复用。
- ADR-047 的“独立页面”展示条款由本 ADR 替代；其服务范围/浮窗分离决策继续有效。
