# ADR-024：初始化恢复与主密钥完整性

- 状态：proposed
- 日期：2026-11-02
- 决策者：待人类确认
- 关联：specs/015-initialization-hardening/{spec,plan,tasks}.md

## 背景

初始化把文件 rename 放在 SQLite 事务中，文件无法随 DB 回滚；已有配置会被默认值覆盖；master.key 缺失时无条件重建；向导写入后继续使用旧运行配置。

## 决策（待批准）

1. 保留密码、Argon2id、IPC 初始化、Passkey 与已有认证来源边界。不删除已有数据、不新增 Web 恢复。
2. 初始化以文件配置为基础，只覆盖向导显式字段；环境变量仍仅是运行覆盖。
3. 在 app_meta 持久化不含秘密的初始化恢复记录。配置文件替换和初始化 DB 提交间故障，下次启动在监听前完成恢复；不能恢复则拒绝启动。恢复的目标是成功提交所确认的配置，未成功提交则还原原配置。
4. 数据库已有加密 secret 时，主密钥缺失、格式错误或无法解密任意记录均拒绝启动，提示恢复正确密钥，不生成替代密钥或删除 secret；空库允许生成。
5. 默认向导复用当前有效网络配置，网络进入高级设置，更新通道沿用配置而不单独询问。初始化变更需重启时，由受管 TUI 在进入仪表盘前停止旧服务、启动并连接新服务；失败退出，保留配置供排障。
6. 不更改默认数据目录，不迁移开发/生产数据；文档指导显式使用独立 LARNESS_DATA_DIR。

## 备选方案

- 删除密码、默认改开发目录：涉及恢复策略/既有数据定位，暂不做。
- 配置全部移入 SQLite：改变配置契约与部署方式，暂不做。
- 密钥丢失自动重置：破坏凭据可恢复性，不采用。
- 配置保存后手动重启：可保留作为故障指引，正常初始化由 supervisor 应用。

## 影响

- 产品：减少无效询问；密码暂保留但不宣称恢复功能已实现。
- API：无 REST/WS 变化，已有 config/IPC 键不变。
- 数据：app_meta 增加非秘密恢复元数据，无破坏性迁移。
- 安全：主密钥异常提前失败；恢复在本机启动前执行；不绕过认证。
- 兼容：既有实例、路径、认证来源保留；错误密钥实例从调用时失败改为启动失败。

## 验证与回滚

文件/DB 故障注入、并发初始化、启动密钥校验、TUI 重启顺序测试与 check/build/E2E。逐任务提交可回退；含恢复记录的数据目录需先用新版完成恢复再回退，不能删除恢复记录来绕过检查。

## 后续

管理员密码的用途单独设计；未来若删除需另立 ADR。本批不增加自动更新能力。
