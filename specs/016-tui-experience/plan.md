# 实施计划草案：TUI 页面与交互统一

> 对应 spec.md；status: draft。本次仅规划，不得据此开始实现或安装依赖。

## 技术方向

- 引入统一的终端屏幕生命周期及页面状态；所有页面输出通过同一渲染入口。管理启动/初始化、进入独立屏幕、隐藏/恢复光标、resize 和退出恢复。
- 页面状态涵盖概览、配对列表/操作/配对码、设备列表/详情/确认、日志、审计和退出确认；键盘事件按页面/输入上下文分发。
- IPC 和 supervisor 复用现有服务层。快照与加载/错误状态由页面管理，渲染只处理展示；配对明文码离页释放引用，不放入全局通知/历史。
- 日志/审计以有限快照呈现，正文换行和滚动，刷新只由用户触发；启动日志/子进程输出仍由 supervisor 捕获。
- 需先验证现有 @inquirer/prompts 与屏幕重绘的组合是否可靠；若不可靠，在实施前比较 Node 内置 readline 与轻量终端库，不预先冻结依赖。

## 分步顺序（均受 G-Spec 门禁）

1. T0-1 页面与导航基础：先写终端生命周期/按键/退出清理测试，建立页面容器、概览、导航、退出确认、失败恢复；保留功能入口可达，不用空占位冒充完成。
2. T0-2 配对与设备：先写列表/确认/码页面停留与错误测试，再迁移实际 IPC 操作；明确回车返回概览、Esc 返回父页，取消不写入。
3. T0-3 日志与审计：先写快照/滚动/刷新/空态与错误测试，再接入现有读取方法；完成各页面无堆叠的真实 PTY 与人工视觉验收。

拟涉及 apps/server/src/tui/ 与对应 test/tui/；是否新增 renderer、screen、input 模块在选型验证后确定，不涉及 Web/DB 迁移。

## 回归、风险与回滚

- 每步 pnpm check / pnpm build，按变化覆盖真实 PTY；信号/退出路径必须验证终端与受管子进程均清理。
- 风险：输入库抢焦点、中文宽度、日志控制字符、异常退出未恢复终端。分别用单一输入所有者、中文布局测试、展示文本过滤与幂等恢复处理。
- 无数据迁移；出现问题按任务提交回退。不能通过改成 headless、忽略权限或吞掉清理错误规避。
- 当前仅是待评审技术方向；不声明实现已完成，不修改现行 IPC 契约或 ADR。
