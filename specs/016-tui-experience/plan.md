# 实施计划：TUI 页面与交互统一

> G-Spec-TUI / ADR-027 已于 2026-11-02 获人类批准；顺序实施完成，2026-11-02 人类验收通过。实际模块和验收见 acceptance.md。

## 1. 技术选型提案

采用 ADR-027：Node 内置终端/键盘能力管理独立屏幕和导航，保留 picocolors；现有 @inquirer/prompts 用于串行的初始化表单。中文列宽与换行采用已在锁文件中的 fast-string-width@3.0.2 / fast-wrap-ansi@0.2.2，批准后才声明为直接依赖，不升级版本或新增原生库。

TerminalSession 是物理 stdin 的唯一所有者，键盘事件按当前上下文分发。初始化表单通过适配器使用受控输入流，普通输入转交 prompt、Esc 通过取消信号结束当前步骤；不得让 prompt 与菜单直接并行读取物理 stdin。prompt 活动时暂停页面重绘，受控借出输出区域，在 finally 回收、恢复原始模式和当前页。无法满足取消/中文/resize 测试时停止选型并记录问题，不绕过验收。

## 2. 模块与内部状态

| 拟议模块 | 职责 | 禁止 |
|---|---|---|
| terminalSession / input | TTY 检查、独立屏幕、输入所有权、受控表单适配、信号/resize/恢复 | 访问 DB、执行业务审批 |
| renderer / text | 过滤外部控制字符、列宽换行、页头/正文/提示、限制到屏幕范围、只绘制当前帧 | 打印未过滤外部文本、创建业务资源 |
| navigation / controller | 页面栈、选中 ID、滚动偏移、输入上下文、加载/错误/结果待确认 | 把返回视为撤销已发送写操作 |
| IPC 页面适配器 | 复用现有 client，Zod 验证返回，5 秒超时、本机请求代号 | 自动重放写请求、改变 RPC 格式 |
| supervisor/main | 既有启动/重启/退出生命周期、捕获子进程输出、向页面提供状态 | 子进程原始日志直接写终端 |

状态至少包含 page、parent、selectedResourceId、scrollOffset、loadState、requestGeneration。日志每个来源分别保存快照/偏移；配对码只存在 code 页面状态，退出该页显式清空引用。导航栈只保存路由/选择，不保存明文码或旧日志。

读请求发出时捕获页面与代号；切页使代号失效，迟到结果不渲染。写请求按本机 single-flight 防重复，发送后只接受全局停止；超时/断线转结果待确认。重连沿用最多 2 次和 5 分钟保活，恢复后废弃旧确认并重新读实际状态。

## 3. 屏幕生命周期

1. 启动任何子进程前校验 stdin/stdout 都是交互 TTY，TERM 不为空且不为 dumb；不满足输出诊断并非 0 退出。
2. 保存进入前输入模式，进入独立屏幕；启动检查、初始化、运行概览均在同一屏幕所有权下显示。
3. 启动/初始化期间不接收业务菜单输入；初始化取消不提交配置并进入既有受管清理；需重启则显示重启状态、关闭旧 IPC、停止旧环境、重新连接，不退出到 shell。
4. 任意时刻仅一个正文页面；resize 在同一页重排，输入期间不抢焦点。低于 80×24 时切空间不足态，暂停业务输入；在途写请求仍接收结果，不伪造取消。
5. 正常退出确认、Ctrl+C、SIGTERM/SIGHUP、未处理错误共用幂等停止流程。先停止 IPC/受管进程，再恢复光标/输入模式/原屏幕；即使清理失败也必须尝试恢复并返回非 0。
6. 停止超时沿用现有 Server 10 秒 / Web 5 秒兜底，不为页面重新设计杀进程策略；SIGKILL/终端崩溃仍受 ADR-023 限制。

## 4. 任务顺序与过渡

1. T0-1：屏幕/输入基础、初始化适配、概览/导航/退出确认与生命周期。先验证输入所有权及实机 PTY。尚未迁移的功能沿用当前实际处理函数，通过受控正文/输入适配接入，仍可操作；阶段验收仅声明基础完成，不将后续页面伪装为已交付。
2. T0-2：替换配对/设备的逐行操作界面，接现有 IPC 与两种批准方式；码页 Enter 到概览、Esc 到配对列表；请求失败/结果不明、撤销确认及结果都在当前页处理。
3. T0-3：日志两个来源快照与审计阅读页、滚动/刷新/空态/错误；整体验证 A1–A16、布局/终端恢复并提交人工视觉记录。

每项预计 1–2 天；实施中若超出任务粒度，先按工作流拆分，不同时执行多个任务。

## 5. 拟涉及文件与回滚

仅 apps/server/src/tui/、对应 test/tui/、针对性测试脚本、server/package.json 和 lockfile 的已批准依赖声明，以及受影响设计文档。不修改 Web、DB schema、业务授权或 RPC 协议号。

按任务提交回退，无数据迁移。T0-1 清理器应作为后续页面共同基础；回退页面时仍保留可靠终端恢复，不能退成 headless 或吞掉清理错误。

## 6. 验证与证据

- 每项先失败测试，再实现，最后 pnpm check / pnpm build；测试只用临时数据目录和空闲端口，不触碰用户运行目录。
- T0-1 已创建 pnpm test:tui:pty，使用 Python 3 标准库 pty/subprocess 驱动 Unix 真实终端；不引入 node-pty。测试机缺 Python/PTY 时明确失败，不静默跳过；不新增产品运行时 Python 依赖。
- 基础 PTY 测试不加载真实凭据，固定假数据；操作重放只含键盘和脱敏状态，不保存真实配对码、Token 或完整终端秘密画面。
- 自动化按 spec A1–A16 与 review.md 的映射验收；截图/人工记录以 100×30、80×24 和 60×16 空间不足态为准。
- macOS 首验；Linux 只有真实运行通过后才记录支持，Windows 另有人工终端验证，不从 Unix PTY 外推。
- T0-1 记录添加两个直接依赖后的构建体积与 Node 20.19 验证；若需要版本变化或额外库，先回到设计评审。

## 7. 风险

| 风险 | 明确处理 |
|---|---|
| Inquirer 与键盘监听竞争 | 一个物理输入所有者，受控输入/输出适配，取消与 finally 回收测试 |
| 日志在阅读中变动 | 只读快照；主动 r 刷新；返回后旧响应失效 |
| 写操作超时后重复执行 | single-flight；结果待确认；只读查询恢复状态，不自动重放 |
| 中文/emoji/长行错位 | 列宽/换行工具、固定视口及真 PTY 尺寸测试 |
| 外部 ANSI/OSC 注入 | 展示前过滤，再添加本机受控样式；恶意控制字符用例 |
| 异常退出留下 raw mode 或子进程 | 幂等清理、finally 恢复、信号/失败注入、恢复前后终端模式比较 |
