# M4 持久运行与版本发布

> 产品范围和完全自主语义按[ADR-042](../../docs/adr/ADR-042-service-deploy-boundary.md)于2026-11-05获人类确认，G-Spec-M4 通过，先执行 M4-0 隔离实验，产品接口和其余实施任务仍受后续门禁约束。M3只交付开发预览；本阶段承接全部PM2持久运行和首次/后续发布。配套[plan](plan.md)、[tasks](tasks.md)、[review](review.md)、[部署契约草案](../../docs/contracts/deployment.md)。

## 1. 目标与非目标
- TUI 初始化检查全局 PM2，缺失时自动全局安装。正式服务由独立 PM2 守护进程托管，Larness 管理进程异常退出或 TUI 正常退出时继续运行，重开后可查看核验过的实际状态。部署和日常管理复用同一 PM2Adapter，负责实例命名空间、受管应用身份、配置、日志、健康、实际状态对账与启停重启。
- 左侧导航与「自动化任务」同级提供「服务运维」独立页面，集中查看和管理授权范围内的正式服务。聊天服务浮窗用于当前开发范围的临时服务与预览。运维入口不依赖当前项目或聊天，部署仍记录来源项目和产物，后端继续核验作用域。见 [ADR-047](../../docs/adr/ADR-047-service-operations-entry.md)。
- 正式运维拥有独立的资源、数据、协议、事件和 Agent 工具执行上下文。两个领域可共用鉴权、策略、锁、审计和模型运行器等基础设施。见 [ADR-048](../../docs/adr/ADR-048-service-domain-separation.md)。
- 构建与不可变产物记录、来源版本、目标服务、影响范围、健康/恢复策略形成持久计划；首次正式运行与版本替换均经过同一部署流程。
- 按策略授权后启动/替换、检查健康、记录实际版本与结果；失败保留日志/状态/支持的恢复入口，停止保留配置和历史。
- autonomous覆盖所有支持的Agent业务动作，首次部署/替换/重启/停止/恢复均免人工审批/确认；标准/严格按风险询问，只读拒绝写入。后端授权、计划完整性、锁、幂等、审计不省略。
- 同版本同配置的日常启停使用服务动作；改变版本/产物/启动配置或环境引用必须进入变更计划，不能用restart端点偷偷替换版本。

非目标：远程主机/Docker、多环境/灰度/集群/CI平台、任意迁移的一键回滚、自动开放公网端口、OS沙箱、M5更新/调度。通用鉴权/权限/秘密/锁保护是每阶段底座，不能留到M4才补；本阶段只补对应部署和持久动作的授权/失败矩阵。

## 2. 用户闭环与状态
正式运维从明确的发布请求开始。核验来源项目、构建输入或不可变产物与正式目标 → 构建或引用已验证产物 → 生成发布计划 → 策略授权 → PM2 首次运行或版本替换 → 健康核验 → 记录版本和结果 → 在「服务运维」查看状态、日志及历史，执行日常操作。开发终端和预览记录不参与正式目标的身份绑定。

部署主线：`VALIDATE → BUILD → PLAN → AUTHORIZE → APPLY → HEALTH_CHECK → RECORD → SUCCESS`；各阶段可进入`FAILED / CANCELLED / UNKNOWN`，不可把未知当成功。BUILD本身执行代码，仍按当前策略授权，不等到部署计划阶段才补授权。
- `AUTHORIZE → WAIT_APPROVAL → AUTHORIZED`仅在当前策略要求人工时出现；批准必须绑定该计划/目标/产物哈希和有限有效期。
- autonomous走`AUTHORIZE → AUTHORIZED`，记录策略允许/真实policySnapshotId/计划哈希/范围后直接执行，不创建人工approvalId、不弹额外部署确认、不等待用户。执行中策略快照固定，切策略只影响后续新动作。
- 计划/产物/目标/当前服务版本变化使旧授权失效，须重新生成计划和策略决策；自主重新决策仍无人工环节。过期/撤销/取消/失效锁或凭据必须拒绝，不能用免人工绕过检查。
- 恢复仅执行已支持且获策略授权的操作；数据库迁移不可逆时明确限制，不虚报自动回滚。自主可自动完成支持的恢复，不把“人工恢复入口”设为其固定停等关卡。

## 3. 验收场景
| ID | Given / When | Then |
|---|---|---|
| D1 | 检查/构建失败或取消 | 不替换运行版本，保留真实失败和有界日志 |
| D2 | 首次部署有效产物/计划 | 在实例命名空间启动正式服务，真实健康后记录版本/结果 |
| D3 | 当前v1，计划发布v2 | 计划绑定旧/新版本及影响，授权后替换，成功才标新版本 |
| D4 | 标准/严格模式需要审批 | 等待真实人工批准；篡改/过期/拒绝后不可执行 |
| D5 | autonomous部署/替换/日常启停/支持的恢复 | 全流程无人工审批或确认停等，有真实策略授权和审计，无伪造人工批准 |
| D6 | 任意模式下未鉴权、scope错、artifact/planHash不符、锁失效或取消 | 拒绝执行，不对无关服务产生副作用 |
| D7 | 健康失败、替换中断、PM2响应或DB结果未知 | 状态真实failed/unknown，先对账不盲目重复spawn；支持的恢复可重试且幂等 |
| D8 | 不可逆迁移或不支持恢复 | 明确能力限制和影响，不保证回滚，不因自主伪造恢复成功 |
| D9 | 人/AI管理同版本同配置的受管服务 | 共用PM2动作/锁/授权/审计，真实启停日志；不误操作其他PM2应用（旧M3 S10） |
| D10 | DB显示RUNNING而实际进程退出/不健康 | observedState对账为stopped/failed/unknown/unhealthy，保留配置/历史（旧M3 S11） |
| D11 | Larness 管理进程异常退出、重开，或正常退出 TUI / 升级 | 异常退出或正常退出时已运行的正式服务继续访问，正常退出清理管理面及临时开发资源。重开后核对实际 PM2 实例、服务身份、版本、配置与健康。缺失或不可验证时显示实际异常或未知。升级涉及 PM2 运行时替换时另行评估影响 |
| D12 | 调用restart却替换artifact/config，或把临时进程当正式服务收养 | 拒绝绕过变更计划；临时仍归终端，不偷偷转PM2 |
| D13 | 同时存在临时开发服务和多个已部署的正式服务，先打开聊天服务浮窗，再从有会话和未选会话的工作区分别进入「服务运维」 | 聊天浮窗仅显示当前开发范围的临时服务和预览入口。「服务运维」只显示授权范围内的正式服务，可查看实际状态、健康、版本、日志和发布记录，并按策略操作。切换视图不影响进程 |
| D14 | 分别为普通开发 Turn 与已授权运维上下文组装实际模型请求，再提交合法工具调用 | 两类模型各自收到适用的服务工具。描述、schema、system prompt 与实际执行范围一致，合法调用各自返回本域结果 |
| D15 | 在任意策略下伪造工具名、上下文或审批，或把另一域的 ID 交给工具、REST、预览、日志、事件订阅或补拉 | 后端拒绝，不返回跨域数据或结果卡，不执行进程操作。自主策略仅在通过领域和作用域校验后免人工 |
| D16 | 同一项目既有临时服务，又从其构建产物发布正式版本，随后终端结束或会话切换 | 正式目标有独立身份及发布历史，可追溯来源项目和产物。临时服务随源退出，正式进程及其状态、日志和事件独立 |

## 4. 接口、数据与配置（设计草案）
正式服务和部署使用独立资源身份、仓储与 DTO，独立于开发服务的 `services` 记录、`/api/services` 和预览接口。新增正式目标的 PM2 绑定、期望/观察状态、产物、计划、授权、部署结果和版本历史。PM2 标识由后端绑定本实例，部署与日常运维共用同一运维模块和 PM2Adapter。见 [部署契约](../../docs/contracts/deployment.md)。
策略授权记录与人工审批记录区分：自主有planHash/policySnapshotId/actor/范围/时效/决策，无人工approvalId；具体schema/状态名/API/配置键在技术评审后冻结，不借本次文档声称已实现。
产物和Larness发布运行数据与项目源码目录分离，准确目录/配额在技术规格确定。秘密仅secretRef引用，受控注入，所有输出/事件/模型脱敏。正式访问地址与管理端隔离预览地址分开，登记/部署不自动开放公网。

普通开发 Turn 不装配运维工具，执行器按后端解析的领域和授权复核。通过运维入口建立独立上下文，目标及项目范围由后端验证。具体入口交互与工具名称在 M4-3b 开工前确定。页面字段或模型输出不能切换执行领域。后端记录真实项目关联、actor、Turn 和策略快照。

## 5. 失败、安全与恢复
PM2事件/查询不等于业务权威提交；关键状态/seq先落库再通知。应用/计划参数、当前受管版本和执行授权在真正apply前重验；单项目/服务写作业使用固定锁顺序与fencing，重复请求不二次替换。构建、迁移、服务进程仍是主机代码执行，不宣称隔离。源文件并发改动和任意外部进程的限制据实说明。
失败先检查PM2/端口/运行版本再决定恢复，不因客户端超时重复启动。无有效策略/范围或未知状态时拒绝副作用；这与自主免人工一致。未经明确能力设计，不自动执行迁移或误恢复数据库。任意模式都不能用直接PM2 CLI绕过本实例ServiceManager的受管操作边界。
