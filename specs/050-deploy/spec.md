# M4 命令行部署与 PM2 服务观察

> 2026-11-07 用户要求撤回本轮专用部署工具改动并重整设计，[ADR-050](../../docs/adr/ADR-050-pm2-cli-deployment.md) 已记录。本轮同时接入通用命令方案，原 M4 后端发布接口保留兼容。实施见 [plan](plan.md) 和 [tasks](tasks.md)。2026-11-07 用户确认 G4 和 M4-R0～R4 全部验收通过，见 [M4 收尾](closure.md)。M4-0～M4-3b 及旧 M4-4 证据描述原实现。

## 目标

Agent 在普通项目会话使用文件和命令工具完成项目检查、构建、准备运行文件、PM2 启动或更新、日志和访问核验。系统告诉 Agent 正式服务由全局安装的 PM2 托管，提供真实可执行入口、实例目录、当前项目和已观察到的服务归属。

正式服务在退出 TUI 后继续运行，重开后按实际 PM2 状态对账。左侧「服务运维」弹窗集中查看实例内的服务、所属项目和日志。开发服务仍归开发终端和预览登记，正式服务通过 PM2 独立运行。

## M4-R1 人工服务控制补充（2026-11-07 用户明确授权）

服务运维采用与项目服务窗一致的列表→详情、状态徽标、信息卡和日志布局，移除“独立于当前聊天”可见文案。认证人类可直接启动、停止和重启已关联服务，不依赖当前聊天策略或构建产物。该入口不注册 Agent 工具，不修改 PM2 应用配置或注入环境。

接口为 `POST /api/service-ops/services/:id/control`，严格参数 `{action: start|stop|restart, expectedPm2Name, requestKey, confirmed: true}`。复用资源操作表，无数据库迁移。执行时复核认证、项目归属、完整 PM2 名称/namespace 和配置身份，按项目→服务获取可续租 fenced 锁；持久化意图与幂等键后操作，事件与结果同事务提交并审计。重复请求不重复重启，结果不确定时需刷新核验，不能自动重试。

验收：Given 列表中的已关联服务，When 进入详情，Then 状态/项目/日志可见且与项目服务窗一致；Given 运行服务，When 取消停止确认，Then 不发请求；When 确认停止/重启或点击启动，Then 操作准确服务并显示 PM2 实际观察结果；Given 无认证/CSRF、身份冲突、并发写锁或同键异参，When 控制，Then 拒绝且不修改进程；Given 已完成相同请求，Then 返回结果且不重复执行。未知/已被删除的 PM2 应用不重建。UI 失败保留提示，启动不宣称健康检查通过。测试覆盖 UI 操作、真实认证 REST 与私有实例 PM2 进程、幂等/失败路径，必要校验后由用户手动验收。

## M4-R2 人工验收纠错（2026-11-07）

控制请求必须使用现有 apiFetch 的 CSRF 选项和对象 body，实际 HTTP 只序列化一次。列表返回实际 pm2Home，界面提供同实例查询命令，保留私有 PM2_HOME，不迁移服务。Given 浏览器确认控制，Then 请求含 CSRF 且 JSON 为对象；Given 本机执行界面查询命令，Then 能查看同一实例。

用户明确批准额外允许读取服务所属登记项目内的 PM2 登记日志（ADR-052）。仅使用实际 PM2 观察到的精确日志路径，并复核唯一名称/namespace/项目归属；仅接受所属项目内或原实例受管目录内的普通文件，不接受符号链接/越界或客户端任意路径。PM2 缺失时仅允许原受管目录的历史日志，不以历史项目路径扩大权限。1 MiB 尾部与脱敏不变。Given 项目内登记日志，Then 可读；Given 其他项目/越界/symlink/身份未知，Then 拒绝。无迁移/依赖，测试覆盖真实 fetch 请求、私有 PM2 与日志正反例；界面人工验收。

## M4-R3 系统服务生命周期契约

系统每次模型请求固定注入两类服务契约，用户无需重复填写区分提示。temporary 的 owner 是受管终端执行、ID 为 svc_，通过 start_project_terminal→实际监听→register_temporary_service→resolve_service_preview 在项目服务窗展示；登记只创建观察/预览身份，不启动/守护/转成 PM2。persistent 的 owner 是实例 PM2，资源 ID 为 tgt_、完整名称关联项目，通过 run_command 构建/PM2 启停，在服务运维展示；不注册为 temporary、不获得开发预览入口。同一项目可同时有两类资源，同名或同端口不等于同一资源，停止/重建各自按真实 owner 操作；退出 TUI 清理临时资源，PM2 持久资源保留，关闭窗口不终止资源。

模型上下文补充本项目已登记临时服务的类型、终端执行、端点和观察状态；PM2 环境与服务保持既有专用摘要。工具描述/schema/登记结果同步 kind=temporary，不增加参数枚举、权限、API/表/依赖或专用部署工具。开发调试/预览任务走临时路径，明确持久运行的任务走 PM2；寿命要求真正不明确时澄清，不由项目脚本名字/当前弹窗/PID猜测。提示词用于语义选择，后端以真实终端监听归属/服务ID与PM2身份校验保证资源边界；通用 Shell 仍不能保证模型不会执行错误命令，不宣称强制命令隔离。

验收：Given 任意用户文本/四种策略，When 组装实际模型请求，Then 固定区分规则和工具/schema 一致；Given 当前项目临时服务和 PM2 服务，Then 分组明确且不泄漏其他项目临时资源；Given PM2 身份或外部端口，When 用作预览/登记，Then schema/真实监听归属拒绝；Given 合法终端监听，Then 仍可登记并预览。测试覆盖实际模型上下文、登记正反例及真实 PM2，不仅核对常量。界面与真实模型交人类验收。

## M4-R4 已删除服务退出当前列表

用户于 2026-11-07 明确要求 PM2 删除后列表消失。可靠完整 PM2 快照确认名称不存在时，持久记录缺失并从服务运维列表及 Agent 当前服务摘要排除；PM2 stopped 仍属于已登记应用，保留在列表。PM2 失联/未知不能当成删除，沿用上次确定的存在性，已确认删除项不会因后续失联重新出现。同名称重新部署时恢复原 targetId。只改变当前列表，不删除项目、运行文件、产物或历史/审计记录，无迁移/新权限/依赖。

存在性复用 service_ops_services.config_json 的内部 pm2Present 标记，与观察状态/事件同事务更新。API schema 不变，既有详情/历史可按 ID 查询；列表刷新后所选已删除项自动退出详情，不继续请求其日志。验收：Given 已停应用，Then 列表保留；When PM2 delete 后对账，Then API/Agent 摘要与弹窗计数/卡片消失；When 失联，Then 未误删且已删不复活；When 同名恢复，Then 沿用关联。定向实际 PM2、状态正反例、Web 查询刷新和必要类型/格式检查，界面人类验收。

## 非目标

远程主机、Docker、集群、自动开放公网、主机开机自启、OS 沙箱和任意数据库的一键回滚。正式秘密注入仍按 Q-029 单独验证。

## 用户流程

1. 用户在项目会话要求部署。系统提供项目身份、PM2 环境、该项目已有服务和发布根目录。
2. Agent 读取项目脚本，必要时用 `update_plan` 记录步骤，确认缺失的业务输入。
3. Agent 经 `run_command` 构建并准备运行目录和 ecosystem 配置，通过有限 PM2 命令启动或替换指定服务。
4. Agent 读取 PM2 状态、有限日志并请求实际服务地址，按证据报告运行和健康。
5. 后端持续观察同一 PM2 实例，把项目关联、进程状态和观察时间持久化并通知界面。用户也可在服务运维入口查看或发起关联项目的普通会话。

命令策略使用真实 Turn 快照。autonomous 无人工停等，standard/strict 按现有风险规则审批，readonly 从系统观察读取服务信息。PM2 服务启动成功后，其生命周期由守护进程接管。

## Agent 工具与系统上下文

复用 `read_file`、`list_files`、`search_code`、`apply_patch`、`run_command`、`update_plan` 以及已有终端工具。模型部署操作以通用命令完成。专用正式服务工具组和部署专用 Turn 入口退出新方案。

上下文与 `run_command` 的实际环境必须同源，包含 PM2 是否可用、Node 与 PM2 的绝对入口、版本、私有 PM2_HOME、命名空间、项目 ID/名称/路径、服务命名模板、本项目发布根目录、服务关联和观察时间。完整字段及示例见 [Agent 命令上下文契约](../../docs/contracts/agent-command-context.md)。

## 服务与项目关联

新服务 `namespace=larness`，名称 `larness:<projectId>:<serviceKey>`，服务 key 不含冒号。一个项目可有多个服务。同名 key 在不同项目仍有不同完整名称。命令操作使用完整名称，项目重命名后关联保持。

后端校验名称、namespace 和登记项目的一致性，并投影为正式服务资源。原 `larness-<targetId>` 名称通过旧目标表恢复项目归属。PID、pm_id、脚本目录和当前选中会话均不作为归属的唯一依据。关联缺失或冲突时显示未关联并避免自动变更该服务。

## 接口与数据

`run_command` 模型参数继续为 `executable`、`args`、项目内相对 `cwd` 和 `timeoutMs`。环境由后端提供，模型不能在工具参数中添加 env、身份或策略字段。命令响应继续包含 commandId、状态、退出码、有界输出和截断标记。

PM2 观察结果继续经鉴权后的 `/api/service-ops/`、正式服务事件和补拉交付。投影复用 deployment_targets 和 service_ops_services，记录 targetId、PM2 完整名称、namespace、projectId、观察状态/时间，当前产物和版本允许为空。DTO 增加 pm2Name/projectName/source，列表返回 unassociated。无新增数据库迁移。旧 `/plans`、`/authorizations` 和 `/apply` 保留兼容，运维 agent-turns 入口已移除。

## 安全与失败

- 通用命令执行主机代码。项目关联和 PM2_HOME 是运行组织方式，不能保证任意 Shell 的目标隔离。
- 参数审批、项目写锁、fencing、幂等键、客户端存活、预算、取消、审计和秘密脱敏沿用命令执行层。不能仅凭命令名称判断任意包装脚本安全或只读。
- 构建失败时先报告失败并保留日志。替换运行目录前保留可恢复的旧文件与启动配置，恢复动作也经过命令策略授权。数据库恢复按项目能力核验。
- 超时、取消或 CLI 失联可能发生在 PM2 已执行副作用之后。先查询实际状态并持久化结果，禁止依据命令超时重复启动。
- `online` 与业务健康分别展示。没有健康检查证据时标记未核验。观察失败标记未知或过期，不能用旧缓存宣称正在健康运行。
- 原始 PM2 环境和 `jlist` 不交模型。日志和命令输出遵循现有脱敏与上限。发布和运行数据置于源码外。

## 验收场景

| ID | Given / When | Then |
|---|---|---|
| C1 | 普通项目会话提出部署请求 | 实际模型请求含通用命令工具及真实 PM2 环境，无专用构建/发布/启停模型工具 |
| C2 | 同一命令在有 PM2 与缺失/失效 PM2 的环境执行 | 使用系统声明的入口和实例，失效时明确失败，避免误接用户默认实例 |
| C3 | 项目 A/B 各启动 api，A 再启动 web | 以完整名称独立运行，Agent 与运维弹窗准确显示服务与项目关系 |
| C4 | 重命名项目、重启 PM2 应用或 Larness | 项目 ID 关联稳定，PID/pm_id 变化得到更新 |
| C5 | 原 `larness-<targetId>` 服务存在 | 通过旧记录展示归属和历史，不自动重命名或重复启动 |
| C6 | 缺失项目、重名歧义、非法 namespace 或失联 | 显示未关联/冲突/未知，避免自动归属和误操作 |
| C7 | 命令构建与首次 PM2 启动 | 构建结果和运行结果可查，实际访问验证后才报告健康 |
| C8 | 版本替换失败 | 据实际文件和 PM2 状态报告失败，已支持的恢复经策略执行 |
| C9 | standard/strict/readonly/autonomous | 按真实命令风险规则处理，命令授权不转为虚假部署审批 |
| C10 | 同项目受管写并发、锁失效、参数替换或重复请求 | 命令执行层拒绝冲突，重试不能重复不确定的 PM2 副作用 |
| C11 | 命令结束/取消或 TUI 正常与异常退出 | 命令子进程得到确认，已托管正式服务按 PM2 生命周期保留，重开后对账 |
| C12 | 模型上下文、输出、PM2 数据、事件或日志含合成秘密 | 受保护秘密被拒绝或脱敏，观察 DTO 不含完整 PM2 env/dump |
| C13 | 两个认证客户端同时观察或从命令更改服务 | 持久状态与事件序号正确，服务运维和开发预览分别展示 |
