# M4 部署闭环与权限加固（草案）

> **状态：draft。** 开始 M4 前补全部署状态机、审批哈希、失败恢复与安全验收。  
> 源设计：`larness.md` 第 4.5、18.4、23、38.2、42.3 章。

## 1. 目标

- 部署流水线：`VALIDATE → BUILD → PLAN → WAIT_APPROVAL → STOP/REPLACE → START → HEALTH_CHECK → RECORD → SUCCESS`。
- 计划持久化：目标服务、变更、影响、构建产物、源码版本、健康检查、回滚说明。
- 审批绑定：计划哈希 + 有限有效期；参数篡改拒绝；审计完整。
- 执行：通过 ServiceManager / PM2Adapter，记录版本；失败保留日志与恢复入口。
- 权限加固：L2 / L3 审批范围、记忆与撤销、审计回放、滥用场景测试。

## 2. 非目标

- 任意部署可一键回滚（数据库迁移可能不可逆）。
- 多环境 / 灰度 / 集群发布。
- CI/CD 集成、远程构建。
- 自动更新（M5）。

## 3. 任务范围（待细化）

| ID | 任务 | 关键交付 |
|---|---|---|
| M4-1 | Validate / Build / Plan | 项目检查、安装 / 测试 / 构建、产物记录、计划生成 |
| M4-2 | 审批 | 计划哈希、范围、有效期、Web 审批卡片、审计、防篡改 |
| M4-3 | Apply / Verify / Record | PM2 启动 / 替换、健康检查、部署记录、失败恢复 |
| M4-4 | 验收与加固 | G4 门禁、失败演练、权限测试 |

## 4. 预验收场景（需补全）

- 构建失败：不产生审批、不替换现有服务，日志可读。
- 计划审批后参数被修改：执行拒绝并审计。
- 审批过期：不可执行，需重新生成计划。
- 部署成功：服务健康、记录版本、旧版本信息保留；重启后对账正确。
- 健康检查失败：保留失败状态与日志；不谎报成功；人工恢复路径清晰。
- 未授权用户 / 会话不能批准部署。

## 5. 待决策

- 构建产物存放位置与保留策略（`artifacts/` vs 项目内）。
- 旧版本保留数量、回滚边界与数据库迁移提示。
- 部署审批是否允许“本会话记住”；默认逐次。
- 健康检查默认策略（HTTP / TCP / 自定义命令）与超时。
