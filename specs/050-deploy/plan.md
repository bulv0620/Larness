# 计划：M4 持久运行与版本发布

> draft，2026-11-06；ADR-042已批准产品分工/完全自主语义，技术G-Spec-M4/PoC尚未通过。

## 实施顺序与复用
0. M4-P 整理 [评审包](review.md)。G-Spec-M4 确认 Q-003、Q-027 候选与实验范围后执行 M4-0。提交 P1–P5 证据并通过 G-PoC-M4，才能进入 M4-1。
1. M4-0承接旧M3-5的PM2交付/实例命名空间、实际身份/进程清理、Q-003/Q-027和退出恢复PoC；不触碰用户PM2实例。
2. M4-1形成Validate/Build/不可变产物/Plan，记录来源/哈希/目标/旧新版本/影响/健康与恢复策略。BUILD也使用当前策略，失败不替换现有服务。
3. M4-2统一计划授权：标准/严格按风险创建审批，自主直接落策略允许，不创建人工批准/确认停等；只读拒绝。计划、产物、目标和时效变化使旧grant失效。
4. M4-3实现唯一PM2Adapter与受管persistent资源、apply/替换/健康/版本结果/实际状态对账，部署复用这一套运行能力；与M3 Registry共用查询/卡片基础，不复用临时进程所有权。
5. M4-3b承接旧M3-5b：持久服务人工/AI工具和卡片详情、日志、同版本启停重启/支持的恢复，拒绝把artifact/config变化伪装restart。
6. M4-4真实首次部署/升级/故障/恢复/两客户端/四策略和G4人类验收，记录平台边界。

## 授权与失败
自主无人工步骤，但actor/scope/policySnapshotId、规范化planHash/artifactHash、有限grant/锁fencing/幂等/预算/取消/审计/秘密检查不可省略。人工审批分支不与策略允许记录混淆。执行任务脱离Turn后的grant生命周期在M4技术评审冻结，不能以无限旧快照持续放行。对账/失败不重复启动，不对数据库不可逆迁移承诺回滚。

## 数据、测试与回滚
M4-1产物/计划记录，M4-2授权记录，M4-3持久配置/PM2绑定/部署历史按依赖单任务迁移，不改已应用迁移；准确拆分和字段评审后冻结。Larness数据/隔离PM2_HOME/测试产物在源码目录外，不写秘密入计划或模型。先失败测试，再真实PM2/HTTP健康/故障与策略验证；按任务风险做必要检查，不能以Mock/没跑测试声称完整完成。回滚代码不删除用户源码/配置/历史，不假定回滚数据库。
