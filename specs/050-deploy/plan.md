# M4 命令行部署接入计划

> 当前设计按 2026-11-07 用户指令和 ADR-050。M4-0～M4-3b 为旧方案已提交记录。

M4-R0 作为一个任务完成本轮改造。

1. 撤回未提交的专用构建、计划、发布模型工具与界面，记录 ADR-050 并同步当前 spec 和契约。
2. 先补普通模型上下文回归。命令执行器注入实际 PM2_HOME 和 PATH，系统上下文公开非秘密的 Node/PM2 入口、项目与发布根、服务关系。
3. 撤回专用运维工具注册和 Agent Turn 入口。复用普通会话工具、审批、项目锁、预算、取消与命令审计。
4. 观察 PM2 的稳定服务名，复用现有仓储持久化项目关联、实际状态和事件。兼容旧服务及发布历史，不改已应用迁移。运维弹窗展示关系并打开对应项目会话。
5. 在临时 prefix 与私有实例完成真实命令构建、两项目同名服务、状态与日志、停止和退出后持久运行验证。运行必要类型/格式和定向测试，记录未跑项后交用户手动验收。

M4-4 按当前 spec 的 C1–C13 收敛 G4。旧 D1–D16 证据用于历史追溯，不自动视为新方案通过。模型 Provider、双客户端、故障与平台边界按实际验证记录。

M4-R1 按用户直接指令实施服务运维 UI 一致性与人工控制：先写 UI 与真实 PM2 回归，再以既有资源操作表持久化幂等意图，固定项目→服务锁顺序，复核认证及 PM2 身份后操作。列表/详情复用项目服务窗的视觉规范；停止/重启需明确确认。只做必要检查，界面交用户手动验收。

M4-R2 修复人工验收发现的实际 HTTP 请求缺陷，先写未 mock apiFetch 的请求边界测试。用户已确认按 ADR-052 扩展所属项目登记日志读取，复用现有读取/脱敏逻辑并补真实 PM2 和路径正反例；列表提供实际实例路径与终端查询命令，保持原私有实例。必要校验后交人类。

M4-R3 统一既有服务领域的系统契约，不新增能力或生命周期。先验证实际 assembleContext，注入固定语义说明与当前项目临时资源摘要，同步工具/schema/登记结果 kind；保留 PM2 环境摘要与现有实际监听/ID/项目校验，运行定向正反例并记录命令执行不构成强制隔离。

M4-R4 先写删除/停止/失联/重建和 Web 刷新回归。完整 PM2 快照持久确认存在性，复用 config_json，无数据删除/迁移；当前列表与模型摘要排除已确认缺失项，历史保持。UI 所选项从列表消失时回到列表、停止日志查询。必要检查后人类验收。
