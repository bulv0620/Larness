# 计划：M4 持久运行与版本发布

> 2026-11-06。G-Spec-M4 已通过，先实施 M4-0。其余产品任务待 G-PoC-M4。

## 实施顺序与复用
0. M4-P 整理 [评审包](review.md)。G-Spec-M4 确认正式服务在正常退出时继续运行，重开后可查看实际状态。提交 P1–P5 证据并通过 G-PoC-M4，才能进入 M4-1。
1. M4-0 承接旧 M3-5 的 PM2 验证。用临时 npm prefix 实测 TUI 初始化的全局检查/补装，用专用 `PM2_HOME` 实测实例身份、异常退出独立性、正常退出策略及重开对账。实验只作用于自己的安装目录和实例。
2. M4-1 形成 Validate/Build/不可变产物/Plan，记录来源项目、哈希、独立正式目标、旧新版本、影响、健康与恢复策略。构建按策略授权，失败不替换现有服务。
3. M4-2 将计划授权绑定运维领域、项目与目标。标准/严格按风险审批，自主直接记录策略允许，只读拒绝写入。计划、产物、目标和时效变化使旧 grant 失效，开发工具授权不可复用。
4. M4-3 将全局 PM2 初始化接入 TUI，实现唯一 PM2Adapter、独立正式资源与仓储、运维协议和事件，覆盖发布、版本替换、健康、版本记录和实际状态对账。发布与日常运维复用这一套运行能力。
5. M4-3b 接入左侧运维页、独立运维工具组和后端授权上下文。运维 UI 与 Agent 共用正式后端，开发聊天只装配本域服务工具。验证实际模型上下文及执行边界，验收 D9–D16。
6. M4-4真实首次部署/升级/故障/恢复/两客户端/四策略和G4人类验收，记录平台边界。

## 授权与失败
自主无人工步骤，但actor/scope/policySnapshotId、规范化planHash/artifactHash、有限grant/锁fencing/幂等/预算/取消/审计/秘密检查不可省略。人工审批分支不与策略允许记录混淆。执行任务脱离Turn后的grant生命周期在M4技术评审冻结，不能以无限旧快照持续放行。对账/失败不重复启动，不对数据库不可逆迁移承诺回滚。

## 数据、测试与回滚
M4-1产物/计划记录，M4-2授权记录，M4-3持久配置/PM2绑定/部署历史按依赖单任务迁移，不改已应用迁移；准确拆分和字段评审后冻结。Larness数据/隔离PM2_HOME/测试产物在源码目录外，不写秘密入计划或模型。先失败测试，再真实PM2/HTTP健康/故障与策略验证；按任务风险做必要检查，不能以Mock/没跑测试声称完整完成。回滚代码不删除用户源码/配置/历史，不假定回滚数据库。
