## 已确定的方向

- **Q-003**　TUI 启动初始化时检查全局 PM2。已装且兼容就直接使用，缺失时由 TUI 自动全局安装。安装范围为启动 TUI 的 Node/npm 环境所使用的全局 prefix。 [PM2 安装说明](https://pm2.keymetrics.io/docs/usage/quick-start/) · [npm prefix](https://docs.npmjs.com/cli/v10/commands/npm-prefix/)
- **Q-027 异常退出**　正式服务由独立的 PM2 守护进程托管。Larness 管理进程异常退出时，已运行的正式服务继续提供访问。Larness 重开后读取 PM2 的实际状态并核对服务身份、版本、启动配置与健康。

- **Q-027 正常退出**　TUI 停止 Larness 管理进程及临时开发资源，保留正式服务。重开后从独立 PM2 实例读取实际状态并对账，缺失或不可验证时显示实际异常或未知。ADR-046 为 [ADR-023](../../docs/adr/ADR-023-tui-as-managed-entry.md) 增加正式服务例外。Larness 更新按安全点处理，涉及 PM2 运行时替换时单独评估影响。

## 实验方案

- 用 npm 的全局安装位置确认 PM2 包、版本和入口，直接通过参数数组调用核验后的 Node 和 PM2 入口。只读安装检查不启动守护进程。缺失时用固定候选版本 `pm2@7.1.2` 试验 `npm install --global`，排除可选依赖和安装脚本。候选版本含环境过滤修复，实际兼容范围和安装参数由 PoC 证据确定。 [PM2 发布记录](https://github.com/Unitech/pm2/releases/tag/v7.1.2) · [npm 版本元数据](https://registry.npmjs.org/pm2/7.1.2)
- 建议安装有超时边界，以当前用户权限运行。遇到已装版本不兼容、npm 不可用、全局目录无写权限或网络失败时，TUI 显示可处理的原因，正式服务管理暂不可用，常规开发功能可继续使用。已有全局版本由用户管理升级。
- 每个 Larness 实例使用源码外的私有 `PM2_HOME` 和专用守护进程，即使同一用户已运行默认 PM2。显式构造客户端、守护和服务的环境白名单。应用名称与命名空间只帮助定位，读写前核对运行实例、服务登记、版本和启动配置。缺失或不一致时停止该操作。 [PM2 多实例说明](https://pm2.keymetrics.io/docs/usage/specifics/)
- 正常退出前停止接收新变更，并让进行中的部署到达可记录的安全点。重开后先对账，守护或进程丢失时记录实际异常，按已授权流程处理。主机开机自启另有系统配置，M4-0 不安装启动项、不从 PM2 dump 批量恢复。 [PM2 API](https://pm2.keymetrics.io/docs/usage/pm2-api/) · [PM2 开机启动说明](https://pm2.keymetrics.io/docs/usage/startup/)
- 仅试验单实例 Node 进程，使用 loopback 测试 HTTP 服务验证实际健康。PoC 使用专用临时目录、合成环境标记和专用测试进程。保留部署和日常服务动作的策略、真实身份、锁与审计。四种策略的完整产品联动按后续任务验证。

## M4-0 实验证据

| 实验 | 验收证据 |
|---|---|
| P1 全局安装初始化 | 用独立临时 npm prefix 实际执行全局安装。验证首次缺失自动安装、重复初始化复用、入口可从源码外使用且探测不启动守护。覆盖版本不兼容、入口漂移、无 npm、权限/网络失败与重试，记录 PM2、Node 和 npm 实测版本。 |
| P2 实例隔离 | 同时运行两个专用临时 PM2 实例，给应用使用同名标识。验证查询、启停、日志和清理只作用于目标实例；拒绝未登记身份、目录越界、符号链接和无法绑定的 socket。 |
| P3 生命周期 | 用真实 TUI 或其受管生命周期测试入口，强制中止 Larness 管理进程并核验同一正式服务 PID 和 HTTP 健康。按批准的正常退出策略另测临时开发资源清理及正式服务状态。重开后核对实际实例、服务、版本、配置和健康。守护不可达或状态丢失时进入对账路径。 |
| P4 状态与失败 | 实际进程、HTTP 健康和持久记录分开。覆盖异常退出、端口占用、无关监听、超时和重复请求，证明确认不了时不会重复启动或影响其他服务。 |
| P5 环境与清理 | 验证环境白名单、输出脱敏和文件权限，检查测试标记未出现在禁止的日志或快照中。结束时确认两个实验实例、进程、监听和测试目录已清理。 |

先以 macOS arm64 提交证据，其他平台按实际结果另列。若观察到实例串绑、无法核验身份或未预期的常驻行为，回到评审。验收记录写入 `poc.md`。
