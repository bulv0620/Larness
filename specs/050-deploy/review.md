## 执行边界候选

- 固定 Node 可执行文件和 PM2 入口，通过参数数组直接调用。显式构造 PM2 客户端、守护和服务的环境白名单。实例私有 `PM2_HOME` 与项目源码分离。应用名称与命名空间只帮助定位，读写前还要核对本地运行实例、服务登记、版本和启动配置。缺失或不一致时停止该操作。 [PM2 多实例说明](https://pm2.keymetrics.io/docs/usage/specifics/)
- 实验验证断开管理客户端后守护进程和服务能否继续运行。正常退出前停止接收新变更，并让进行中的部署到达可记录的安全点。重开后先对账，守护或进程丢失时记录实际异常，按已授权流程处理。主机开机自启另有系统配置，M4-0 不安装启动项、不从 PM2 dump 批量恢复。 [PM2 API](https://pm2.keymetrics.io/docs/usage/pm2-api/) · [PM2 开机启动说明](https://pm2.keymetrics.io/docs/usage/startup/)
- 仅试验单实例 Node 进程，使用 loopback 测试 HTTP 服务验证实际健康。PoC 使用专用临时目录、合成环境标记和专用测试进程。保留部署和日常服务动作的策略、真实身份、锁与审计。四种策略的完整产品联动按后续任务验证。

## M4-0 实验证据

| 实验 | 验收证据 |
|---|---|
| P1 发布物 | 记录 PM2 精确版本、完整依赖锁、体积及实际 Node 版本。从脱离源码的发布候选目录启动。缺失、版本不符或运行路径漂移时报告错误。 |
| P2 实例隔离 | 同时运行两个专用临时 PM2 实例，给应用使用同名标识。验证查询、启停、日志和清理只作用于目标实例；拒绝未登记身份、目录越界、符号链接和无法绑定的 socket。 |
| P3 生命周期 | 用真实 TUI 或其受管生命周期测试入口核验正常退出、重启和中断。记录管理入口、临时开发资源和 PM2 正式服务各自状态。守护不可达或状态丢失时进入对账路径。 |
| P4 状态与失败 | 实际进程、HTTP 健康和持久记录分开。覆盖异常退出、端口占用、无关监听、超时和重复请求，证明确认不了时不会重复启动或影响其他服务。 |
| P5 环境与清理 | 验证环境白名单、输出脱敏和文件权限，检查测试标记未出现在禁止的日志或快照中。结束时确认两个实验实例、进程、监听和测试目录已清理。 |

先以 macOS arm64 提交证据，其他平台按实际结果另列。若观察到实例串绑、无法核验身份或未预期的常驻行为，回到评审。验收记录写入 `poc.md`。
