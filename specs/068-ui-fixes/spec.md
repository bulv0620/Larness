# 发布后界面与输出纠错

用户于 2026-11-11 提出并确认七项问题的修复范围，按任务顺序逐个实施、验收和提交。

## 目标

修复凭据添加后的数据刷新、完全自主确认按钮悬停可读性、服务关联终端输出、Header 版本显示、自动化空态布局、表单一致性和操作失败提示。

## 非目标

新增业务能力、授权策略、调度规则、终端生命周期和第二套 UI 框架不在本轮范围。

## 验收场景

1. Given 打开模型设置，When 添加 Key 成功，Then 凭据列表和模型选择数据自动更新，官方目录按现有同步能力自动刷新，用户无需刷新页面。目录同步失败时保留已保存 Key 并显示可恢复错误。
2. Given 打开完全自主确认弹窗，When 鼠标悬停、键盘聚焦或按钮禁用，Then 亮暗主题中按钮文字与底色可辨，原有确认行为保持一致。
3. Given 服务关联到产生中文、英文和 ANSI 控制序列的终端，When 查看历史并接收新增输出，Then 输出可读、中文跨块完整、控制序列得到正确处理，重开视图不重复输出。读取失败可恢复，终端归属校验继续有效。
4. Given 打开含下拉框和表单的业务界面，When 使用鼠标与键盘编辑和提交，Then 使用现有 Radix / @larness/ui 体系统一封装，选择值、校验、禁用、焦点与弹层滚动行为正常。保留文件选择等平台专用输入，普通输入使用统一样式组件。具体控件清单在实施前盘点。
5. Given 开发启动或安装包运行，When Header 渲染，Then 显示该运行版本的有效版本号。版本读取失败显示稳定占位，避免 undefined 和错误版本。
6. Given 自动化任务加载成功且列表为空，When 展示空占位，Then 占位在列表可用区域水平、垂直居中，在窄屏和窗口缩放后仍可见。加载失败提供错误反馈。
7. Given 文件、Git 或其它业务操作失败，When 展示反馈，Then 使用统一浮动错误 message，避免插入占据业务布局的单行红字。消息可关闭、可被辅助技术感知，同一失败避免重复弹出。表单字段校验和需要持续操作的冲突恢复提示保留就地语义。消息使用既有安全错误映射，不展示秘密或原始异常。

## 接口与数据

优先复用现有 REST / WS、版本注入、目录同步与终端读取契约。逐项诊断后如需契约修改，同步对应 contracts 与测试。数据库结构和持久配置沿用现状。

## 安全与权限

所有资源操作沿用后端鉴权、项目归属、授权、锁和审计。凭据明文只进入现有受控提交路径。错误消息及测试产物不得包含 Key、Cookie、Token。完全自主按钮的修改仅涉及呈现。

## 失败与边界

覆盖慢请求、失败重试、弹窗关闭后的异步返回、重复操作、空数据、亮暗主题、键盘导航。终端检查历史回放与增量一致性，编码修复须依据实际输出链路，避免重复解码。未验证的平台据实记录。

## 测试计划

每任务先写失败回归，再最小实现。按组件及数据链路补充对应测试，运行 pnpm check，涉及构建与版本时运行 pnpm build，并进行相关浏览器验收。记录每项实际运行命令、结果和未验证范围。

## UI-F8 对话执行展示

用户于 2026-11-11 选定「简洁对话」并要求与工作区风格统一。保持三栏和现有单列宽度，沿用共享控件、字体与语义 token。

- Given 执行中或有待处理审批，When 滚动历史或展开过程，Then 当前状态在滚动视口下方可见；审批操作仍由既有面板处理。只有可用的运行态才显示活动提示。
- Given 同轮包含工具调用，When 收起过程，Then 以探索、修改、命令及其他操作分类计数；失败工具的名称或摘要仍可直接展开。计数为调用次数，失败与重试均保留。
- Given 展开执行记录，When 打开一条命令的详情，Then 仅该命令的状态及输出按现有授权查询加载。
- Given 最终回复、过程说明或已产生的结果，When 浏览对话，Then 正文、次级说明与成果易区分；复制、时间、审批、滚动跟随和终态后展示成果的行为沿用。
- Given 浅色、深色及 320px 窄屏，Then 状态、长命令和消息可读，无横向溢出。

呈现使用已有 Turn、工具、审批和命令数据。无需变更 API、WS、持久化、权限或推理重放。无已知命令退出码时使用已有失败状态，详情按授权读取真实退出码。测试覆盖折叠时的失败入口、按需加载、实时状态及主题和窄屏。
