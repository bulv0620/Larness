# 发布后界面与输出纠错

用户于 2026-11-11 提出并确认七项问题的修复范围，按任务顺序逐个实施、验收和提交。

## 目标

修复凭据添加后的数据刷新、完全自主确认按钮悬停可读性、服务关联终端输出、Header 版本显示、自动化空态布局、表单一致性和操作失败提示。

## 非目标

新增业务能力、授权策略、调度规则、终端生命周期和第二套 UI 框架不在本轮范围。

## 验收场景

1. Given 打开模型设置，When 添加 Key 成功，Then 凭据列表和模型选择数据自动更新，官方目录按现有同步能力自动刷新，用户无需刷新页面。目录同步失败时保留已保存 Key 并显示可恢复错误。
2. Given 打开完全自主确认弹窗，When 鼠标悬停、键盘聚焦或按钮禁用，Then 亮暗主题中按钮文字与底色可辨，原有确认行为保持一致。
3. Given 服务关联到产生中文、英文和 ANSI 控制序列的终端，When 查看历史并接收新增输出，Then 输出可读、中文跨块完整、控制序列得到正确处理，重开视图不重复输出。读取失败可恢复，终端归属校验继续有效。
4. Given 打开含下拉框和表单的业务界面，When 使用鼠标与键盘编辑和提交，Then 使用现有 Radix / @larness/ui 体系统一封装，选择值、校验、禁用、焦点与弹层滚动行为正常。保留文件选择等平台专用输入，普通输入使用统一样式组件。具体控件清单在实施前盘点。
5. Given 开发启动或安装包运行，When Header 渲染，Then 显示该运行版本的有效版本号。版本读取失败显示稳定占位，避免 undefined 和错误版本。
6. Given 自动化任务加载成功且列表为空，When 展示空占位，Then 占位在列表可用区域水平、垂直居中，在窄屏和窗口缩放后仍可见。加载失败提供错误反馈。
7. Given 文件、Git 或其它业务操作失败，When 展示反馈，Then 使用统一浮动错误 message，避免插入占据业务布局的单行红字。消息可关闭、可被辅助技术感知，同一失败避免重复弹出。表单字段校验和需要持续操作的冲突恢复提示保留就地语义。消息使用既有安全错误映射，不展示秘密或原始异常。

## 接口与数据

优先复用现有 REST / WS、版本注入、目录同步与终端读取契约。逐项诊断后如需契约修改，同步对应 contracts 与测试。数据库结构和持久配置沿用现状。

## 安全与权限

所有资源操作沿用后端鉴权、项目归属、授权、锁和审计。凭据明文只进入现有受控提交路径。错误消息及测试产物不得包含 Key、Cookie、Token。完全自主按钮的修改仅涉及呈现。

## 失败与边界

覆盖慢请求、失败重试、弹窗关闭后的异步返回、重复操作、空数据、亮暗主题、键盘导航。终端检查历史回放与增量一致性，编码修复须依据实际输出链路，避免重复解码。未验证的平台据实记录。

## 测试计划

每任务先写失败回归，再最小实现。按组件及数据链路补充对应测试，运行 pnpm check，涉及构建与版本时运行 pnpm build，并进行相关浏览器验收。记录每项实际运行命令、结果和未验证范围。

## UI-F8 对话执行展示

呈现使用已有 Turn、工具、审批和命令数据。无需变更 API、WS、持久化、权限或推理重放。无已知命令退出码时使用已有失败状态，详情按授权读取真实退出码。测试覆盖折叠时的失败入口、按需加载、实时状态及主题和窄屏。

## UI-F14 Header 服务端资源占用

2026-11-11 用户要求 Header 右侧显示服务侧系统的 CPU、ROM（磁盘）和 RAM 占用。此前只在 Mock 中显示随机模拟值，真实 Server 没有主机资源数据。

- Given 已认证打开工作区，When Header 渲染，Then 右侧显示运行 Larness Server 的机器的 CPU、RAM、磁盘占用环形仪表；不读取浏览器所在设备的数据。数值每 4 秒刷新。
- Given 鼠标经过三枚环形仪表区域，Then 光标变为手型并出现圆角选中框，但不弹出内容。
- Given 点击三枚环形仪表区域，Then 区域保持选中框并弹出资源详情卡；卡片逐项显示 CPU 百分比、RAM 与磁盘已用 / 总量及百分比，无标题栏，仅三行内容，带阴影与指向触发区的尖角。再次点击、点击区域外或按 Escape 关闭，辅助技术仍可读取隐藏的精确摘要。
- Given Server 刚启动、首次采样还未完成或磁盘占用不可读，Then CPU 或对应资源显示 `—`，不把占位 `0` 当作真实占用。
- Given 窄屏、浅色或深色主题，Then 资源块在 `xl`（1280px）以下隐藏，其余尺寸不挤压项目名和右侧操作；颜色沿用工作区语义 token。
- Given 演示 Mock 模式，Then 使用固定 Mock 值保持视觉 Demo 可用；Mock E2E 不访问真实指标接口。

数据来自新增的已认证 `GET /api/system/metrics`，契约见 [REST API](../../docs/contracts/rest-api.md#get-apisystemmetrics已认证)。CPU 使用 `os.cpus()` 增量，内存使用 `totalmem - freemem`，磁盘使用 Server 数据目录所在卷的 `fs.statfs`。变更不涉及数据库、权限、审批或持久化。

## UI-F15 项目列表拖拽排序

2026-11-12 用户直接要求「项目列表支持一下拖拽调整项目顺序」。排序是工作空间数据而非单浏览器视图偏好，因此由 Server 持久化，所有客户端看到同一顺序。

- Given 项目列表含两个以上登记项目，When 直接按住项目条目并拖到另一项目上方或下方，Then 显示插入位置，松开后项目移动到该位置；列表立即更新并写入 Server。项目行不额外占用左侧拖拽按钮空间。
- Given 拖拽过程中经过列表底部或最后一个项目，When 松开，Then 项目移动到列表末尾；拖拽回原位不发送写请求。
- Given 用户用键盘聚焦项目条目，When 按方向键上 / 下，Then 项目上移或下移一位并按同样规则持久化。
- Given 项目已展开会话，Then 会话区域相对项目条目缩进，并用现有左侧竖线区分层级，不贴侧栏左边缘。
- Given 默认工作区或搜索过滤中，Then 默认工作区固定首位且不可拖动；有搜索条件时禁用拖拽，避免只对可见子集排序。
- Given Server 拒绝排序（项目已被其他客户端新增 / 移除、未认证、校验失败），Then 客户端恢复原顺序并显示统一错误消息；不留下只在本浏览器生效的顺序。
- Given 新增项目，Then 新项目追加到当前自定义顺序末尾，而不是重新按更新时间打乱既有顺序。
- Given 浅色、深色与窄侧栏，Then 手柄、拖拽态与插入线沿用工作区语义 token，不遮挡项目名和新建会话按钮。

数据变更：`projects` 增加 `sortOrder`（迁移 `0027`）；`GET /api/projects` 按该列升序返回，默认工作区仍固定首位。新增已认证、需 CSRF 的 `PUT /api/projects/order`，body `{ projectIds: string[] }` 必须恰好覆盖全部登记项目（不含 `prj_default`），原子写入并审计 `project.reordered`。接口与错误码同步到 [REST API](../../docs/contracts/rest-api.md#7-工作区与模型)。不新增依赖，不改变项目目录、会话、Agent 工具或授权范围。
