# DeepSeek 官方接入与上下文用量

本切片排入 M5-1，依赖 M4 通过 G4。

Larness 当前内置 `deepseek-chat`，将窗口配置为 128,000 tokens。上下文圆环用一轮内多次模型请求的累计输入量除以该窗口，调用工具较多时会提前显示满格。DeepSeek 官方目录提供模型窗口和思考档位。 [官方模型列表接口](https://api-docs.deepseek.com/api/list-models/) · [官方模型规格](https://api-docs.deepseek.com/quick_start/pricing/)

## 范围

- 官方配置使用 `deepseek-flash` 作为默认候选。设置页用已配置凭据刷新官方目录，模型选择器提供已验证兼容的模型。名称、窗口和可用档位以官方元数据为准。
- 输入框提供关闭思考和所选模型支持的档位。官方当前示例包含低、高、最高。选择在创建 Turn 时固定，对本轮每次模型请求生效。 [官方思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)
- 圆环用最近一次有统计的模型请求的输入 tokens 除以同次请求的模型窗口，提示明确写出单次输入占比。当前轮次有新统计时更新，空闲时显示所选模型最近一次可用统计。整轮累计输入、输出和总量保留原口径。
- 本切片范围为 DeepSeek 官方端点、模型选择、工具续跑和用量显示。GLM、通用兼容端点发现、上下文压缩与跨模型迁移属于 M5-1 的其余范围。

## 验收场景

| 场景 | Given | When | Then |
|---|---|---|---|
| A1 官方目录 | 已配置有效 DeepSeek 凭据 | 在设置页刷新目录 | 显示官方返回的兼容模型、窗口和档位。默认候选为 `deepseek-flash` |
| A2 目录失败 | 已有一次成功同步的目录 | 凭据失效、限流、超时或元数据缺失 | 保留可用的上次记录并显示刷新状态。未验证的窗口和档位显示为未知 |
| A3 思考设置 | 所选模型提供多个档位 | 以「高」发送，再在运行中切换档位 | 本轮每次请求继续用「高」，下一轮用新选择。非法档位在后端拒绝 |
| A4 工具续跑 | 在官方端点开启思考 | 任务连续调用工具，再在同会话发下一轮 | 已授权的工具正常执行并返回最终答复。同模型推理数据按官方协议回传 |
| A5 圆环口径 | 同一轮两次模型请求各有 40,000 和 80,000 输入 tokens，窗口为 1,048,576 | 第二次用量到达，随后刷新页面 | 圆环按 80,000 显示约 8%，累计输入记录为 120,000 |
| A6 历史与模型切换 | 旧记录只有累计用量，或已有统计来自另一模型 | 打开旧会话或切换模型 | 圆环显示「暂无统计」，直到所选模型有可匹配的单次统计 |
| A7 鉴权 | 请求来自未认证客户端 | 读取目录或尝试刷新 | 服务端拒绝请求，且不调用上游 |

## 接口、数据与权限

- REST 沿用模型 Profile 的边界，增加官方目录刷新和可选模型能力字段。Turn 创建接受可选思考设置，服务端校验并固定模型、凭据引用、窗口和档位。
- 单次请求用量随事件重放恢复。仅公开模型标识、单次输入量、窗口等展示字段。兼容旧累计数据并保留既有 Profile 与历史 Turn 的关联。
- 目录请求由服务端访问固定的官方地址，复用现有 Secret Store。目录缓存按凭据范围隔离。目录不可用或上游拒绝工具续跑时显示明确状态，模型或档位变化由用户选择。
- 厂商私有推理数据限后端同会话、同模型按协议回传，禁止进入 REST、WebSocket、可见对话、日志和跨模型上下文。工具调用沿用现有授权、审批、锁、审计与预算。 [工程宪法](../../CONSTITUTION.md) · [官方工具续跑要求](https://api-docs.deepseek.com/guides/thinking_mode/#tool-calls)

## 验证

- 契约测试覆盖目录校验、缓存隔离、鉴权、上游错误和各档位的请求参数。
- 运行时测试覆盖连续工具调用、同会话后续轮次、切模型和脱敏。使用授权测试凭据验证官方端点。
- 圆环测试覆盖累计值与单次值不同、缺少统计、刷新重放和切模型。认证浏览器验收模型选择与档位设置。

## 待确认

1. 既有内置 `deepseek-chat` 由用户选择迁移，还是只对内置默认配置自动迁移到 `deepseek-flash`。同时确认未选择档位时采用官方默认还是保留现有交互习惯。
2. 先验证同模型跨轮及进程重启后的官方续跑要求，再确认推理数据的恢复方式、保留范围、有效期和清理机制。

转为 `ready` 前需确认上述决策，并同步 REST、WS 和数据契约。
