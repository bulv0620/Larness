## MC-0 规格与评审包

交付 [规格](spec.md)、[实施计划](plan.md)、[拟议契约](../../docs/contracts/model-connections-draft.md) 与 [ADR-062](../../docs/adr/ADR-062-model-connections-and-capabilities.md)。核对引用、上游接入条件、迁移和门禁。本任务提交只包含方案。

## MC-1 预设与迁移

涉及 `apps/server/src/modules/models`、Drizzle 和 API 合同。覆盖现有 GLM 四端点、DeepSeek、兼容 URL 迁入，保留凭据、默认值、历史和已有绑定。并发换 Key 测试新旧 Turn 的版本边界。执行 A1、A7、A9 的连接层场景。

- 2026-11-14 交付迁移 0028、经认证的预设 API、改名与带版本校验的换 Key。预设从既有 provider／端点推导。旧端点修改 API 保留兼容。已创建的目录 Turn 固定 Key、端点和预算。
- 自动化验证旧版数据库引用保留、升级前备份、待执行 Turn 的旧 Key 与预算、终态清理旧密文、旧目录请求失效，以及 API 验证和鉴权。`pnpm check` 与 `pnpm build` 通过。整仓检查曾在文件监听 PoC 超时，单跑及整仓复跑通过。
- 多平台接入、设置 UI、能力目录和真实 Key 回归由后续任务验收。

## MC-2 目录与预算

涉及 Provider 目录解析、Turn 上下文预算与持久化缓存。逐字段同步 DeepSeek，合并 GLM 目录，开放按模型覆盖或登记。先测未知状态、上游数值口径、缓存竞争、预算和输入长度，再接入远程补充。执行 A5–A7、A9 的目录与预算部分。

- 2026-11-14 交付 0029、逐字段来源、单连接刷新、手动登记及覆盖接口、DeepSeek 上游能力解析、总窗口与输入／输出限制、现有选择器按可用档位展示。
- `pnpm check`、`pnpm build` 与目录、接口权限、缓存、运行预算专项通过。Models.dev 实际请求返回 403，公共目录合并由测试夹具验证。设置操作入口由 MC-3 接入，真实平台验收由各平台任务记录。

## MC-3 设置与选择

涉及 `ModelSettingsDialog`、`ModelControl`、Composer、Web API 客户端与相关认证 E2E。增加连接和模型两页；支持搜索、默认、可见性、测试状态与连接二级选择。验证两种主题、键盘和窄屏，以及默认值和计费线路。执行 A1、A4–A6。

## MC-4 OpenCode Go

固定套餐目录、推理端点与会话请求头，按 Go 预设匹配能力。目录 mock 校验字段和认证失败；报文 mock 锁定稳定会话 ID、工具格式和上下文预算。用真实 Go Key 跑列表、一次流式工具调用及续步。执行 A2、A9。

## MC-5 阿里云百炼

按量地域与业务空间、Coding Plan、Token Plan。解析原生目录分页并区分套餐额度与限流。逐预设跑 A3、A9、A10，记录未验证线路。

## MC-6 Kimi

开放平台与 Kimi Code 国内／国际。验证模型目录或候选来源，保持真实客户端身份，验证流式工具回传。逐预设跑 A3、A9、A10。

## MC-7 MiniMax

开放平台国内／国际与 M Plan。按官方格式编码同 Turn 工具续跑和思考参数，处理流中业务错误。逐预设跑 A3、A7、A9、A10。

## MC-8 截图

端到端覆盖受管附件、历史回放、权限、图片额度、切换纯文本模型和草稿保留。用已经验证支持图片与工具的线路跑 A8、A9，并同步 Agent 工具契约中受影响的模型上下文与执行验收。

## 完成条件

真实验收证据按平台和预设逐项记录。单任务门禁包括对应专项与 `pnpm check`，最终运行构建、认证及生产 E2E。进度同步到路线图和 STATUS。
