# 模型连接、能力目录与平台接入

## 1. 背景与目标

现有设置和会话按 Key 展开目录。同款模型会重复出现，目录成功也无法说明模型实际可调用。GLM 上新时，缺少窗口的型号无法在会话使用，通用兼容网关则可能把连接级的 128,000 token 缺省值套给多个模型。模型目录只保存少量字段，运行时和输入框难以判断具体模型的工具与图片能力。见 [063 规格](../063-multi-provider/spec.md) 和 [ADR-053](../../docs/adr/ADR-053-model-catalog-thinking.md)。

- 设置中能添加并管理一个平台的多个 API Key，用户能看清请求去哪里、使用哪份额度。
- 模型上新可以通过刷新目录或逐模型补充能力启用，常规元数据更新独立于 Larness 程序版本。
- 补齐百炼、Kimi、MiniMax 和 OpenCode Go；迁移 DeepSeek、GLM 和现有 OpenAI 兼容连接。
- 建立逐模型、逐协议的能力判定，并以截图输入验证 Composer、预算与 Provider 序列化整条链路。

本切片覆盖聊天和 Agent。音视频、任意文件、图像生成、账号登录授权、套餐购买、自动跨账号或跨计费线路切换另行规格化。

## 2. 用户交互

### 模型设置

设置第一层是 Key。桌面用左侧 Key 列表、右侧模型和连接状态，窄屏在模型区上方横向浏览 Key。Key 名称、平台、额度和模型数量在导航可见，选中 Key 后在其详情管理同步、编辑、删除和登记。目录暂不可用时仍可找到已保存的 Key。

模型区按当前 Key 搜索。模型行显示上下文窗口短值及图片、工具和思考图标；悬停或聚焦显示说明，触屏也可展开模型详情。缺少窗口或工具等影响选择的状态用短文字标注。默认、可见性、测试调用和能力覆盖操作以当前 Key 和模型为作用域。

添加 Key 时先选择平台，只为有多个接入预设的平台显示 Key 来源。保存后选中新 Key 并显示同步结果；保存成功后目录失败仍保留连接。

DeepSeek 和 OpenCode Go 直接选平台、粘贴 Key。GLM 根据 Key 来源显示「智谱国内 · 标准 API」「智谱国内 · Coding Plan」「Z.AI · 标准 API」「Z.AI · Coding Plan」，地址在详情展示。其他多接入平台用同样的交互。无法确认计费路径时由用户选择 Key 来源，Key 前缀最多用于提示。更换同来源的 Key 保留连接 ID；改用不同接入预设或主机应新建连接并显式迁移引用。

同步只读取目录。显式测试发送一次有界的合成请求，结果标为具体模型和协议的「已验证」。目录状态显示「未同步／已同步／旧缓存／目录不可用」。调用状态显示「待验证／已验证／鉴权失败／权限不足／额度耗尽／限流／暂不可用」。候选模型来自平台目录、已知目录快照或手动登记；界面区分来源及验证状态。

### 会话左下角

收起时只展示模型名及其可用的思考档位。展开后第一层按 Key，显示名称、平台和额度，默认展开当前 Key 并标出当前模型。点击其他 Key 在原位展开，再选择模型。可按 Key 或模型搜索，结果保持 Key 分组。思考选项位于面板底部。已保存会话绑定、当前 Turn 快照和额度失败时的处理沿用既有行为；两把 Key 上的同款模型各自在其组内显示。

该交互按 [ADR-063](../../docs/adr/ADR-063-key-first-model-ui.md) 更新。以现有模型、连接 ID 和权限契约为边界，不修改接口、数据模型、目录或 Provider 行为。

## 3. 平台范围

| 平台 | 首批预设 | 目录策略及运行要求 |
|---|---|---|
| DeepSeek | 官方 API | 读取官方模型列表及其窗口、输出、模态、effort。保留现有协议映射和旧会话 |
| 智谱 GLM | 国内／国际各有标准与 Coding Plan | 按连接读取模型列表，缺项由对应预设的能力目录补齐。端点来自固定的官方预设 |
| 阿里云百炼 | 标准 API（地域预设，支持官方工作空间域名）、Coding Plan、Token Plan | 标准连接优先读取可用的工作空间原生目录。各套餐使用自身端点和候选表，目录字段缺失时可手填。分别映射工具与思考参数 |
| Kimi | Kimi 开放平台与 Kimi Code，分别提供官方国内／国际端点 | 独立 Key 来源。按连接读取可用目录或使用该预设目录候选。报文保留真实客户端标识，按官方要求验证工具调用 |
| MiniMax | 国内／国际开放平台，各支持标准 Key 与 M Plan（Token Plan）Key | 官方文档核对每种接入与可用模型。同一地区地址可服务不同 Key 时仍区分额度。验证流中业务错误、思考模式和同 Turn 工具回传 |
| OpenCode Go | Go 套餐，一个预设一把 Key | 使用 Go 目录与 Chat Completions 路径，附稳定会话标识。GLM、DeepSeek、Kimi 等都按 Go 的实际可用模型处理 |
| 自定义 OpenAI 兼容 | 公网 HTTPS Base URL | 支持单独登记模型和逐模型能力覆盖。继续校验目标与限制重定向 |

OpenCode 需求按此前明确的 Go 订阅纳入。OpenCode Console 按量付费可通过后续独立预设接入。各平台的交互式套餐按官方适用范围启用；后台 Scheduler、批处理或其他用途仅使用允许对应场景的连接。未知用途规则需在真实接入验收中核实。

## 4. 能力与错误语义

- 以字段为单位保存来源和时间。优先级为用户明确覆盖、同一线路可信上游字段、匹配该线路的版本化目录、随包内置快照。探测结果用于诊断具体请求，短请求不能推断最大窗口。
- 区分总上下文、最大输入、最大输出、思考档位及映射、输入和输出模态、工具调用、流式。能力可为支持、不支持或未知。预算同时遵守已知的总量和输入／输出边界。无法解析的字段保持未知，用户可以填有效的逐模型配置。
- 目录同步对当前连接版本原子落库。失败保留上次成功数据并显示错误；较早的响应不能覆盖换 Key、停用或迁移后的状态。连接与模型权限仍由请求时的真实结果体现。
- Turn 创建时固定连接、凭据版本、发送的模型 ID、协议、能力和预算。用户修改设置、目录更新只影响后续 Turn；进行中引用的凭据版本按运行生命周期释放。
- Provider 私有思考可按已有 Turn 内存边界用于续步，由适配器映射；历史重放、跨模型切换和恢复继续使用标准上下文。
- 图片验收只覆盖输入。Composer 保留截图草稿并预检合适的连接。服务端校验授权、MIME、体积和数量，通过受管附件引用组装请求。历史消息和摘要体现附件是否可重新发送。

## 5. 接口、持久化、安全

拟议请求和返回字段见 [契约草案](../../docs/contracts/model-connections-draft.md)。继续用现有连接 ID 引用会话、默认值、隐藏设置和历史 Turn。迁移新增预设与连接版本，兼容读取旧缓存与旧 REST 调用，旧版网关的有效窗口保存为带来源的旧配置，详情可逐模型修正。

模型权限和工具执行沿用 [工程宪法](../../CONSTITUTION.md)、[安全架构](../../docs/architecture/security.md) 与 [Agent 工具契约](../051-agent-tool-contract/spec.md)。远程能力目录只接收经校验的元数据，地址、授权头、协议执行代码和密钥由本机运行配置控制。所有带 Key 的目录与推理请求使用连接选定的主机，禁止在探测、重试或失败时迁往其他域名、线路或账单。配置写入经过鉴权、CSRF 和审计。

## 6. 验收场景

| | Given | When | Then |
|---|---|---|---|
| A1 | 已有 GLM、DeepSeek、兼容凭据及默认值 | 升级并打开新旧会话 | 原连接 ID、默认值、隐藏项、档位和历史可读，模型调用仍走原端点 |
| A2 | 有一把 Go 套餐 Key | 添加 Go 并选 GLM 或 DeepSeek | 同一个连接下看到多个厂商的可用模型，真实流式工具调用和续跑使用 Go 路径及稳定会话头 |
| A3 | 百炼、Kimi、MiniMax 分别有正确的标准与订阅 Key | 对拟交付预设执行目录和真实 Agent 测试 | 匹配的 Key 用指定地址调用。按线路记录发现、流式输出、工具续跑、用量和验证状态 |
| A4 | 两把 Key 都提供同款模型 | 切换会话的连接；随后套餐耗尽 | 模型各自在所属 Key 下显示。明确显示所选账单来源。错误分类准确，草稿保留 |
| A5 | GLM 新 ID 缺窗口，DeepSeek 新 ID 带完整字段 | 同步并给 GLM 补值 | GLM 可见且提示缺项，补值后可用；DeepSeek 在字段齐备后直接可用。刷新不抹掉手工覆盖 |
| A6 | 目录超时、损坏或换 Key 时旧刷新返回 | 读取设置与选择器 | 旧缓存标注状态；无其他连接串用；旧响应不能改变新版本的数据 |
| A7 | 正运行的 Turn 已固定模型和预算 | 更换 Key、改能力或刷新目录 | 续步仍用原快照，下一 Turn 才使用新配置。历史和跨模型上下文无厂商私有推理 |
| A8 | 一条线路支持图片和工具，另一条仅文本 | 粘贴截图、切纯文本再切回并发送 | 草稿保留，纯文本路径在请求前拒绝；真实图片与工具续步成功，日志与事件无附件字节 |
| A9 | 未授权客户端、恶意目录、内网地址或欠费 | 尝试刷新、测试或发起 Turn | 禁止越权、地址注入、跨线路重试和秘密泄漏，返回稳定且可操作的错误 |
| A10 | 已注册只限交互使用的套餐 | Scheduler 或批处理试图使用它 | 发送前拒绝，交互会话继续正常使用 |

### MC-9 界面验收

| Given | When | Then |
|---|---|---|
| 两把 Key 都有同款模型 | 从会话左下角打开面板并切到另一把 Key | 当前 Key 默认展开，选择操作绑定展开组的凭据 ID。收起后仅模型名及适用的思考档位 |
| Key 下存在图片、工具、思考和窗口字段 | 浏览模型，并聚焦图标或打开详情 | 能力摘要与实际字段一致，详情可读，未知字段与明确不支持可区分 |
| 有已经保存的 Key 但目录加载失败 | 打开设置或重试同步 | Key 仍可见并可操作，目录失败和测试调用状态独立 |
| 模型被隐藏或缺少运行所需能力 | 在设置和会话中浏览同一 Key | 设置显示原因，缺项可补。会话筛选保持原有规则，不自动改用其他连接 |

## 7. 测试和决策

先写会失败的单元、集成测试。主路径覆盖数据库迁移、服务端校验、组装报文、预算、工具续步和真实认证 UI。每个宣称支持的线路用合法持有的真实 Key 验证，记录地区、预设、模型、协议、交互范围与结果。没有真实 Key 的线路保留待验证，测试夹具模拟的通过单独记录。

[ADR-062 草案](../../docs/adr/ADR-062-model-connections-and-capabilities.md) 已确认开始实施，目录来源与信任范围见 [Q-038](../../docs/open-questions.md#已解决)。方案首批覆盖上述标准及订阅预设，OpenCode 按 Go 处理；图片接入在管理和平台任务后交付。账号不可用或平台规则待查的具体路径见 [实施计划](plan.md)。

自动化、公开目录和真实账号待验收范围见[验收记录](acceptance.md)。
