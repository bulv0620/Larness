# 082 Agent 内核重构：K-10 A/B 验证

> 生成日期：2026-11-18（macOS arm64，Node v24.22.2）。
> 结论先行：**确定性 A/B 已完成，10/10 任务在两个 Profile 均成功；coding 固定工具开销下降 57.5%，总估算输入下降 56.4%。真实模型 A/B 未运行**，没有可用 Key/预算授权，不能把本报告当成模型成功率证明。

## 1. 方法与边界

- 脚本：`apps/server/scripts/kernel-ab.ts`。
- 使用 `createFakeProvider` 回放**同一组 10 个脚本化任务**；每个任务在 `coding` 与 `workspace` 各新建一个项目、会话与 Turn，工具轨迹、步数和工具调用完全相同。
- 因此本报告可比较：
  - Profile 的固定工具 schema 与 system 差异；
  - 同一轨迹下的累计估算输入差异；
  - 功能可用性与执行结果（文件、命令、锁、审批、审计）。
- 本报告**不能**比较：
  - 真实模型在两种工具面下的成功率、步数、选择质量或幻觉率；
  - 真实用户任务中的审批等待、测试/构建命令占比与计划触发率。
- 会话审批策略设为 `autonomous`，避免人工审批停等；锁、路径、版本、秘密与命令安全路径仍真实执行。
- 输入 token 使用仓库现有 `estimateRequestTokens()` 估算，不是 Provider 实际计费 token。

| Profile | 工具数 | 首次请求工具 schema token | 10 任务 Provider 调用 | 工具调用 | 累计估算输入 token | 相对 workspace |

| `coding` | 7 | 1 462 | 29 | 19 | 52 378 | **-56.4%** |
| `workspace` | 17 | 3 440 | 29 | 19 | 120 238 | 基线 |

- 工具 schema 节省：`(3 440 - 1 462) / 3 440 = 57.5%`。
- 累计输入节省：`(120 238 - 52 378) / 120 238 = 56.4%`。
- 两者调用次数与工具调用数完全相同，差异来自每个请求重复发送的工具 schema 与 system 段落，而不是任务执行路径。
