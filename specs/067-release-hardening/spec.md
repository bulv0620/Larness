# 安全复核、发布清单与文档定稿（M5-5）

> 状态：`done`（2026-11-08）。G5 按人类确认的 macOS 当前范围条件通过。Windows / Ubuntu 待实机，详见 [遗留问题](../../docs/open-questions.md)。

## 1. 背景与问题

M5 已完成多 Provider、调度器、npm 分发与 macOS Apple Silicon 支持；M5-3 已把 `larness@0.1.0` 发布到公共 npm。剩余风险不是新功能，而是：

- 安全边界分散在 ADR、契约和代码中，缺少一份可执行的发布前复核清单；
- 发布/升级/降级流程依赖人工，容易遗漏版本、构建、包内容和数据库备份；
- Windows / Ubuntu / macOS 的支持范围与限制尚未集中公开；
- G5 的旧验收条款仍写着“签名更新 / 自动回滚”，与 M5-3 的 npm 方案不一致。

M5-5 把这些问题收口为可复核的文档、清单和门禁记录。

## 2. 目标

- **G-1 安全复核**：按身份、认证、审批、秘密、日志、预览、PM2、调度、更新、备份逐项核对实现，列出通过 / 部分 / 未验证与残余风险。
- **G-2 可重复发布**：给出一份从版本号到 npm publish、安装验证、回滚/降级的人工 checklist；不依赖 CI。
- **G-3 文档定稿**：安装、升级、降级、卸载、支持矩阵、已知限制、故障恢复与安全边界集中可查。
- **G-4 G5 一致**：把 G5 从旧的签名更新/自动回滚改为已确认的 npm 提示方案；未完成的三端验证必须显式保留。
- **G-5 可审计**：M5-5 自身只改文档；不修改认证、审批、锁、数据模型或已发布行为。

## 3. 非目标

- **NG-1 新功能**：不新增 Provider、调度、更新下载器、Windows 终端或 PM2 功能。
- **NG-2 CI**：不配置 GitHub Actions 或其他 CI；三端验证由人类实机执行。
- **NG-3 自动更新 / 签名发布包 / 自动回滚**：M5-3 已决定只提示 npm 更新；不在本切片恢复。
- **NG-4 代替三端验收**：Windows / Ubuntu 结果必须由实机提供；文档不得写成已通过。
- **NG-5 代码重构**：除非复核发现必须修复的安全缺陷，否则只改文档。

## 4. 用户故事

- 作为维护者，我希望发布前逐项勾选检查清单，避免漏掉构建、包内容、测试或数据库备份。
- 作为新用户，我希望从文档明确知道支持哪些平台、Node 版本和限制。
- 作为安全复核者，我希望看到每个威胁对应的实现与残余风险，而不是一句“已加固”。
- 作为验收者，我希望 G5 条款与实际产品一致，不要求已废弃的签名更新器。

## 5. 验收场景

### A1 安全复核清单

```gherkin
Given 当前代码、ADR、契约
When 执行安全复核
Then 每一项包含结论（通过 / 部分 / 未验证 / 不适用）、证据路径、残余风险
And 不把未验证项写成通过
```

### A2 发布前检查

```gherkin
Given 版本号已更新
When 按发布清单执行
Then 完成 install / check / build / platform-smoke / npm pack 安装 / publish dry-run
And 记录 npm 版本、tarball 内容、Node / OS、失败项
And 不在清单未完成时发布
```

### A3 安装 / 升级 / 降级文档

```gherkin
Given macOS Apple Silicon 用户
When 阅读安装文档
Then 能看到 npm 安装、TUI 更新提示、手动升级、降级、卸载、数据库备份与恢复
And 明确不支持 macOS Intel
```

### A4 支持矩阵与限制

```gherkin
Given Windows 11 / Ubuntu / macOS Apple Silicon
When 阅读支持矩阵
Then 每个平台的已验证 / 未验证功能、原生依赖、终端/PM2 限制可见
And Windows 终端/命令未实现不会被写成支持
```

### A5 G5 一致性

```gherkin
Given 旧 G5 要求签名校验、失败回滚
When 更新门禁
Then 采用 npm 提示 + 手动安装 + 升级前备份 + 人工回滚/降级
And 保留三平台实机结果与未验证项
```

### A6 文档不作为验证

```gherkin
Given M5-4 尚无 Windows / Ubuntu 结果
When 完成 M5-5 文档
Then G5 只能按人类明确确认的范围记录条件通过
And 文档明确等待实机，不以文档代替验收
```

## 6. 功能需求（文档 / 复核）

| ID | 级别 | 需求 |
|---|---|---|
| R-1 | MUST | 安全复核覆盖：认证 / Passkey / CSRF / Origin / HTTPS、IPC/TUI、Agent 工具与审批、项目锁、Secret Store、日志脱敏、预览隔离、PM2/部署、调度器、npm 更新检查、升级前备份。 |
| R-2 | MUST | 每项给出结论与证据路径；无法验证的项标 `未验证`，不得写“通过”。 |
| R-3 | MUST | 发布清单包含版本、构建、测试、包内容、临时安装、dry-run、真实 publish、tag、安装验证、回滚/降级。 |
| R-4 | MUST | 发布清单明确“无 CI”；所有命令可本地执行，Windows / Ubuntu 由人类实机执行。 |
| R-5 | MUST | 文档集中列出支持矩阵（macOS Apple Silicon、Ubuntu、Windows 11）与 Node 20/22/24。 |
| R-6 | MUST | 明确不支持：macOS Intel、Windows 终端/命令/PM2（当前）、WSL 冒充 Windows、自动更新、签名发布包。 |
| R-7 | MUST | 安装文档覆盖 npm 全局安装、`larness` 启动、TUI 更新提示、手动升级、降级、卸载、数据备份/恢复。 |
| R-8 | MUST | 更新 G5 条款，使其与 M5-3 npm 方案一致；未验证平台保留为发布后跟踪。 |
| R-9 | MUST | 记录安全残余风险：非沙箱、任意命令/脚本、原生依赖、PM2 非安全边界、Monaco CSP、网关/代理配置等。 |
| R-10 | MUST | 不修改代码行为；若发现必须修复的安全缺陷，另开任务，不在文档任务中夹带。 |
| R-11 | SHOULD | 文档链接到 ADR / 契约 / 验收记录，避免复制过期细节。 |
| R-12 | SHOULD | 发布清单提供可复制命令和检查表，减少人工遗漏。 |

## 8. 数据与迁移

- 无数据库变更；不改迁移、配置、契约语义或已发布 npm 版本。
- 发布清单继续要求升级前自动备份（M5-3 已有）与降级前恢复备份。
- 文档中的版本、命令与当前 npm `0.1.0` 对齐；未来发布时更新。

## 9. 安全与权限

- 本切片只读代码与文档；不执行发布、不修改 npm 包、不改认证/审批/锁。
- 复核不得记录秘密、Cookie、Token、密钥或未脱敏日志。
- 文档不得宣称沙箱、自动更新、已签名发布包或未验证平台支持。

## 10. 失败、边界与恢复

| 场景 | 行为 |
|---|---|
| 发现安全缺陷 | 停止 M5-5 文档、记录问题、另开修复任务；不把缺陷写成已通过 |
| 三端结果缺失 | G5 按人类确认的范围记为条件通过；其余平台标“待实机” |
| 发布清单任一步失败 | 停止发布；保留日志与 tarball；修复后重跑 |
| npm publish 成功但安装失败 | 立即 `npm deprecate` / 发布补丁；文档记录回滚命令 |
| 数据库迁移失败 | 使用升级前备份恢复；不假设旧代码兼容新 schema |

## 11. 测试 / 验证

- 文档链接、命令、版本与实际仓库/npm 对齐。
- `pnpm check` / `pnpm build` / `platform-smoke` / `verify-npm-pack` 在 macOS 上复跑（文档任务不改代码，作为基线）。
- 不要求 Windows/Ubuntu 在 M5-5 内完成；由 M5-4 实机结果补齐。
- 安全复核以代码路径、契约、ADR 和既有测试为证据。
