# M2 开发资源与窗口层

> 2026-11-02 人类要求开始 M2，并明确“按最新spec来”；G-Spec-M2 / ADR-029 已批准。2026-11-03 人类明确开始 M2-1，G-PoC-M2 通过；M2-1 / M2-1b 已验收，M2-2 已实现待 review，后续任务未启动。配套：[plan](plan.md)、[tasks](tasks.md)、[review](review.md)、[资源契约](../../docs/contracts/m2-resources.md)、[ADR-029](../../docs/adr/ADR-029-development-resource-execution.md)、[PoC 记录](poc.md)。

## 1. 背景与用户目标

M1 已有真实项目、会话、Agent 文件工具、审批、事件重放和项目写锁；S0 已有窗口、Monaco / xterm 展示及布局。缺少的是把文件、命令、PTY 和 Git 接入真实资源管理，允许用户在模型不可用时独立操作。复用现有代码，不将 Demo 中的状态当作真实后端能力。

源设计：`larness.md` 4.4 / 4.6 / 4.7、17–18、36–38、42.2。上位约束为宪法、已冻结 ADR、安全模型与 [resource-views](../../docs/contracts/resource-views.md)。

## 2. 目标与非目标

目标：

- 文件树懒加载、完整文本读取与保存、内容版本校验、外部修改通知；Monaco 多 Tab 与冲突恢复。
- Agent 用 CommandRunner 执行有限时长的非交互命令；流式查看输出，支持超时、取消、截断与进程清理。
- 真实 PTY / xterm，多个客户端观察同一资源，一个输入租约，窗口隐藏后可恢复；Agent 可为前端 / 后端等常驻 dev 进程分别创建项目终端 Tab。
- Git status / diff / log / 分支列表，结构化 add / commit / 创建与切换分支 / ff-only pull / 普通 push；后端审批与锁。
- 全局窗口按资源身份去重、来源分组、项目筛选、本地布局恢复；文件、终端和 Git 不依赖模型服务。
- 从每个写能力首次上线起就执行锁与 fencing 校验，最后再集中做并发验收。

非目标：

- 服务托管、端口登记、预览代理和浏览器真实预览（M3），部署（M4），更新 / 调度（M5）。
- 文件新增、删除、重命名、上传下载、二进制编辑、大文件分块编辑；已有文件编辑以外的文件操作另立任务。
- Git reset / clean / force push / 删除分支 / 修改远端 / rebase / merge 冲突编辑器；不提供任意 Git 参数输入框。
- 未经授权接管用户终端、向模型暴露或自动填写主机凭据、控制终端以外的桌面程序；AI 的终端输入 / 中断 / 人工交接须走统一租约与工具权限。
- 临时 PTY 跨 Server 重启恢复、跨设备同步窗口布局、OS 沙箱、全平台支持承诺。
- 删除会话与 artifacts 的清理策略（Q-011 保持待决，本期只归档）。

## 3. 产品行为与安全边界

### 3.1 文件

以项目 ID 或独立会话 ID 解析授权根目录，不接受裸绝对路径作为授权依据。同文件 viewKey 仍按 realpath 去重，origin 只用于展示。保留 M1 默认忽略 `.git` / `node_modules` / `.larness` 与项目 ignore 的现有匹配语义；本期不扩展成完整 gitignore 语法。忽略是展示规则，不能代替路径授权。

编辑模式必须读取完整 UTF-8 文本和原始字节 SHA-256，保留换行；不得把 M1 按行截断的工具输出当编辑底稿。草案上限为文件内容 512 KiB，超出只提示不支持编辑；JSON 仍受现有 1 MiB 上限约束。二进制、无效 UTF-8、符号链接和非普通文件拒绝编辑。每次保存携带 expectedVersion；加锁后再次校验路径、版本与文件身份。文件监听只作提示，正确性依赖保存时重读版本。

本地未保存内容在窗口隐藏和项目切换时保留；关闭脏 Tab 必须选择保存 / 放弃 / 取消，刷新前提示可能丢失。M2 不把未保存源码写入 localStorage。外部变更时干净 Tab 可重载；脏 Tab 保留草稿，展示差异并允许重新加载或手动合并后基于新版本保存，不提供静默强制覆盖。

### 3.2 命令

CommandRunner 使用 executable + args 数组和 `shell: false`；需要 Shell 语义时显式调用固定 Shell 的 `-c`，按任意脚本 L2 逐次审批。可信项目中常规 test / build / lint 等沿用 L1 策略；识别为常规开发只决定审批，不证明安全。未知命令默认 L2，L3 默认拒绝；审批策略不得因为命令名看似安全而允许任意参数。

默认超时 120 秒，最大 600 秒，且不得超出 Turn 剩余预算；stdout + stderr 合计最多 1 MiB，达到上限后继续排空但不继续存储 / 推送，最终标 truncated。输出来自有界缓冲，实时增量不充当权威状态。非零退出是失败，可查看退出码与脱敏输出。取消必须停止整个受管进程组，不能只停止等待 Promise。断开浏览器或关闭窗口不取消命令，显式取消 / Turn 取消 / 超时 / TUI 退出才触发停止。

### 3.3 终端

创建时确认“以 Larness 系统账户执行，项目目录不是沙箱”。项目终端 cwd 在项目授权根内；独立会话终端在其 workspace 内。无项目 / 无会话的全局终端使用 dataDir 下专用 workspace，不接受任意主机 cwd。人工可创建 Shell 终端；Agent 可创建绑定项目、启动参数和用途标识的开发进程终端，不将任意 Shell 输入逐条归类为安全命令。

人工输入租约绑定后端认证会话 + 当前连接，AI 租约绑定真实 Turn / executionId 与发起认证会话；同一终端只允许一个 principal 控制，不信任客户端或模型 owner 字段。暂定 30 秒 TTL / 10 秒续租；只允许当前持有者输入和 resize。其他人可观察、等待到期或由原持有者释放；人工之间不强抢，人工可显式接管 AI 租约，原子撤销其 generation，AI 不自动抢回。断开、登出、撤销即停止接收该连接输入并释放输入租约；未绑定旧连接的新租约不得接收迟到输入。

**一次性命令与常驻开发进程按用途分流**：测试 / 构建等有结束点的任务使用 CommandRunner；`pnpm dev`、前后端 watch 等常驻任务由 Agent 通过 `start_project_terminal` 创建真实项目 PTY。前端与后端分别使用用途标识（如 frontend / backend），产生两个 terminalId / Tab。后端先持久化资源与创建事件，再返回 terminalId；发起客户端插入该项目分组、origin=agent 的 Tab，不抢走当前焦点，其他客户端只更新资源列表，不强制打开窗口。

Agent 可用 `read_terminal_output` 按游标读取有界输出，或用 `stop_project_terminal` 显式停止；不把完整日志反复灌入上下文。启动返回“进程已启动”，不能只凭 spawn 成功宣称服务 ready。若启动立即退出，终态 / 退出码应可见。相同项目 + 用途标识的活跃资源重复启动复用，参数不一致返回 CONFLICT；不能自动杀掉重建。重新执行 Turn 不重复启动前后端。已成功创建的终端归项目所有，Turn 完成 / 取消、用户切会话或关闭 / 最小化窗口都不停止它；主动关闭终端 Tab 则请求后端终止；创建尚未成功交付前的取消必须清理未交付进程。

**锁设计修订（ADR-029 已批准）**：撤回“所有 PTY 存活期持续持有项目写锁”的初稿建议。开发运行终端不长期占用源码写锁，因此同项目可同时运行前端 / 后端，并继续 Agent 编辑和文件保存。文件修改、Git 写、一次性写命令仍使用项目锁 / 内容版本。dev 脚本或人工 Shell 可能写缓存 / 生成文件，输入租约、用途标识与 cwd 都无法保证其不修改源码；此类进程须明确作为不受源码写锁串行保证覆盖的主机写者，监听与版本校验处理可观测冲突。模型不能仅把任务标为 dev 就绕过普通写命令审批和锁：开发终端启动须逐次 L2 批准，展示完整规范化程序 / 参数 / cwd 及并发写风险；明确的迁移 / 格式化 / 安装 / 批量改源码任务仍走写命令路径。

该锁例外已随 G-Spec-M2 / ADR-029 获批准，作为源码写锁保证范围的补充，不修改冻结旧 ADR 原文。M2-0 仍须验证受管进程清理；脱组进程不能被宣传为可完全约束。M3 按 ADR-030 提供临时服务登记 / 展示 / 预览及 PM2 持久服务能力；临时源进程只由 Terminal 控制，不能因服务登记重复启动进程，不应把 M2 的 PTY 启动成功冒充服务健康或已登记预览。

### 3.4 Git 与审批

不使用 Shell 拼 Git 字符串。读操作禁止 external diff / textconv 等外部执行，路径使用参数分隔符；本机 Git 缺失返回能力不可用。add 只接受显式路径；commit 只提交已暂存内容，不自动 add -A。分支创建 / 切换要求工作区及暂存区干净。pull 只允许 ff-only 且工作区干净；push 只推当前分支到已配置上游，不改远端、不 force。远端认证依赖主机既有 Git 配置，不提供网页密码输入，禁用交互提示并设置超时。

add / commit / 创建与切换分支属 L1，Agent 仍按 Turn 策略；pull / push 为 L2 逐次审批。人工操作不虚构 Agent Turn，使用新的资源动作记录绑定实际客户端、规范化参数、仓库快照和有效期。审批后还需执行请求；重新取锁、重验 HEAD / index / 目标分支及远端摘要，变化即使审批失效。Agent Git 工具复用同一 Manager，保留 M1 Turn 审批关联。

## 4. 验收场景（Given / When / Then）

| ID | Given 前置 | When 操作 | Then 预期 |
|---|---|---|---|
| A1 | 已授权项目或独立会话 | 展开目录、打开文本 | 真实树懒加载，完整内容 / 原字节版本，默认忽略规则生效 |
| A2 | 已读取 v1，磁盘仍为 v1 | 编辑保存 | 锁内校验成功，内容与新版本一致，持久化变更事件后通知其他客户端 |
| A3 | 脏 Tab 基于 v1，外部已写 v2 | 保存或收到监听通知 | VERSION_CONFLICT，草稿保留；可看差异 / 重载 / 手工合并，不覆盖 v2 |
| A4 | 恶意路径、外链或扫描中替换文件 | 读写 / 枚举 | 拒绝越界与不支持类型，失败审计；无根外内容或写入 |
| A5 | 二进制 / 无效 UTF-8 / 超限文本 | 打开编辑 | 明确不可编辑；不将截断内容保存回原文件 |
| A6 | FakeProvider 提出常规测试命令 | 授权后执行 | 真实子进程运行，流式脱敏输出；完成状态落库；无自动终端 Tab |
| A7 | 命令输出超限、退出非零或超时 | 执行结束 | 有界内存 / 输出；truncated、退出码、超时原因准确，受管子进程树清理 |
| A8 | 命令运行中 / 等待审批中 | 取消 Turn | 审批作废；无后续工具；现有子进程停止，确认停止后释放锁 |
| A9 | 两个已认证浏览器观察同一 PTY | 争取输入租约、输入、resize | 只接受持有连接当前租约；另一方只读，租约 owner / 到期时间可见 |
| A10 | 当前控制者断线、过期或被撤销 | 旧连接继续输入，新客户端申请 | 旧输入拒绝，新租约可取得；PTY 仍保持，输入租约不控制源码写锁 |
| A11 | PTY 运行且有 Tab / 筛选历史 | 关闭 / 最小化窗口、切项目、刷新后顶部恢复 | 同一 terminalId，无新建 PTY / 终止请求；本地筛选 / 分组 / 激活恢复，其他客户端布局不变 |
| A12 | 项目 A 已有 frontend / backend 开发终端，另有受锁保护的写任务 | A 编辑保存 / 写 Turn / Git 写，B 写作业 | dev 进程不因编辑停止；受锁保护的 A 写任务互斥，无重叠路径的 B 可并发；dev 外部写造成的版本冲突拒绝覆盖 |
| A13 | Git 仓库有工作区与暂存修改 | 查询 status / diff / log，选择 add / commit | 展示真实结构化状态；区分 staged / unstaged / untracked；仅选中路径入暂存 |
| A14 | pull / push 等待审批 | 未批准执行、改参数、换 HEAD 或重复执行 | 默认拒绝；过期 / 拒绝 / 快照变化作废；一次批准不可重复触发远端副作用 |
| A15 | 脏工作区或 ff-only pull 无法快进 | 切分支或 pull | 返回可恢复冲突，不自动 stash / merge / reset；原文件保留 |
| A16 | 未授权、坏 Origin / CSRF 或伪造资源 ID | REST、订阅、输入、回放 | 一律后端拒绝；来源标签和前端项目筛选不能授权 |
| A17 | 旧持有者租约失效，进程停止未确认 | 新写作业申请锁、旧请求迟到 | 不并发接管；旧 fencing token 不得写 / 续租 / 释放新锁；无法证明停止则项目阻塞 |
| A18 | 执行资源活跃 | Server 崩溃再启动 | 原 PTY / 命令标 INTERRUPTED，不伪造恢复；未确认孤儿写作业进程前不开放冲突写作业 |
| A19 | WS 断线、事件缺口、输出游标已过期 | 重连 / 补拉 | 关键事件按序补齐；过旧返回 resyncRequired，明确输出缺失，不伪造完整历史 |
| A20 | DB / 审计 / 输出落盘失败 | 创建或状态变更 | 不广播成功；不执行新副作用；已有进程进入停止 / 受阻处理，错误可诊断 |
| A21 | 有固定测试秘密、敏感环境变量 | 文件、命令、Git、PTY 输出及错误 | 受保护材料不注入任意进程；输出统一脱敏，跨块匹配；响应 / 日志 / 事件扫描无假秘密 |
| A22 | 模型 API 离线，文本 Tab 有未保存改动 | 操作文件 / Git / PTY 或关闭 Tab | 资源功能独立可用；脏 Tab 提供保存 / 放弃 / 取消，拒绝覆盖时保留草稿 |
| A23 | M2 资源运行中 | 退出受管 TUI | 停止 Server、Web、PTY 与命令并清理；关浏览器 / 资源窗口不触发此行为 |
| A24 | 同一 realpath 经不同来源打开 | 打开文件、Git Diff、资源 Tab | 文件按 realpath、Diff 按 projectId + path 去重；来源 / 分组 / 筛选遵循冻结视图契约 |
| A25 | Agent 要启动同项目的前后端 dev | 两次 start_project_terminal，分别 frontend / backend | 审批后创建两个真实 PTY，项目终端列表与发起客户端两个 Tab 可见；不自动抢焦点 |
| A26 | 相同用途终端已活跃，Agent 重试或下一 Turn 再启动 | 参数相同 / 不同 | 相同返回原 terminalId，参数不同 CONFLICT；不重复启动、不自动杀旧进程 |
| A27 | 开发终端已成功交付，Agent 后续编辑并结束 / 取消 Turn | 保存、读日志、关闭窗口 | 两 dev 进程保持运行；输出有界读取；主动关闭终端 Tab / 显式停止才终止对应资源，创建交付前取消则清理未交付进程 |
| A28 | 运行 PTY 被两个客户端查看 | 一方关闭终端 Tab，或终止失败 | 成功终止后发起者移除 Tab、另一方 ended；失败保留 Tab / 错误；M3 联动临时服务退登，不复活资源 |
| A29 | Agent 修改文件，结果附文件卡片 | 点击 / 重复点击 / 目标已变化 | 按 scope / path 授权解析、打开 / 聚焦文件 Tab；不重新执行修改，失效显示明确状态 |
| A30 | Agent 已持某项目终端控制租约 | 输入 / 中断 / 释放，或 Turn 取消 | 只接受当前 principal + generation；输入重试不重复按键；中断需查实际结果；取消撤销租约而不自动停止已交付终端 |
| A31 | Agent 正控制终端 | 人工显式接管后旧 Agent 继续输入 | 原子交接，新 generation 生效；旧输入拒绝，AI 不抢回，客户端与 Turn 看到控制权变化 |

关闭规则按 [ADR-030](../../docs/adr/ADR-030-resource-lifecycle-and-services.md) / [资源视图契约](../../docs/contracts/resource-views.md) 执行。服务窗口没有服务 Tab。临时服务注册 / 退登、预览结果卡片在 M3；M2 提供准确的终端执行 / 退出身份和事件，供后续绑定，不把 M3 功能算作 M2 已完成。

文件工具修改结果在 M2 补结构化 file target 与可点击文件卡片；Browser 卡片在 M3 只绑定已登记、已验证服务。AI 完整终端控制的 acquire / input / interrupt / release、人机 principal、人工显式接管和 Turn 取消只撤销控制权的技术草案已补入 [m2-resources §10](../../docs/contracts/m2-resources.md)，由 M2-4d 实施验收；具体 schema 仍须 G-Spec-M2，不把 start / read / stop 三个工具当作完整交互验收。

## 5. 接口、数据与配置

详细字段、REST / WS、错误码、表结构、默认上限见 [m2-resources](../../docs/contracts/m2-resources.md)。这是拟议契约，现有接口不因本文自动变更。

- 文件接口补齐显式 scope；新增 CommandExecution、Terminal、ResourceAction 和资源事件重放。
- 资源状态及 seq 在同一事务落库后广播；PTY / 命令输出使用独立游标，不占用关键事件 seq。
- 复用 M1 `resource_locks`，不重复建项目锁。新增表按所属任务分别迁移，每任务最多一份迁移。
- 不改变 IPC 协议号、Cookie、canonical origin、Passkey、初始化与统一入口；资源管理通过既有已认证 REST / WS。
- 暂不增加持久配置键。上限作为共享常量先验证，未来配置化须补 schema / 契约 / 测试。

## 6. 失败、权限与恢复

全路径继承认证、Origin、CSRF、限流和授权守卫；审批 / 锁 / 资源归属不明失败关闭。命令白名单、cwd、锁和环境过滤均不构成 OS 沙箱。

环境只继承必要的 PATH / HOME / 临时目录 / locale / TERM（具体各平台清单在 M2-0 验证），不继承管理服务 Token、LLM Key、代理认证和任意 NODE_OPTIONS；M2 不给任意命令 / PTY 注入 SecretStore 明文。Shell 启动文件仍可能访问主机凭据，风险在执行确认中说明。脱敏覆盖已知秘密及敏感字段，不宣称可识别任意程序输出中的全部未知秘密。

文件写与 SQLite 不构成同一事务：先持久化写意图 / 审计，再执行校验与写入，最后提交结果与事件；中途失败标记待对账，不报告成功、不自动回写旧内容。M2-0 验证 fd / 路径身份校验与原子替换策略；外部程序最后校验后的竞争无法靠应用锁彻底排除，不能承诺对任意外部写者的原子 CAS。

长进程在锁续租失败时先停止进程组；不确认清理成功不允许仅按 TTL 给新作业放行。重启对未知活跃资源先对账；不得凭 PID 杀死可能复用该 PID 的无关进程。PTY 不恢复原交互状态；输出回放不是进程恢复。

审计至少记录文件写、命令创建 / 结束 / 取消 / 超时、终端创建 / 终止 / 租约交接、Git 计划 / 审批 / 执行 / 拒绝、锁丢失 / 恢复。带 requestId、clientSessionId、projectId / scope、resourceId；Agent 再带 sessionId / turnId / toolCallId / policySnapshotId / approvalId。人工动作不得伪造 Agent 标识，不记录输入正文、完整环境和原始秘密。
