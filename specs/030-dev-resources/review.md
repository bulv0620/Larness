## 需要人类确认的取舍

| 项目 | 建议 | 直接影响 |
|---|---|---|
| Q-021：交互终端占用写锁 | 项目 PTY 整个存活期持锁，输入控制权另设短租约 | 同项目只能一个活跃 PTY；运行期间文件保存 / Agent 写 / Git 写受阻，先终止终端再重试 |
| Q-022：验证路径 | 设计批准后先 M2-0，node-pty + 原生目录监听 / 对账，真实 macOS 与 built 入口 PoC | PoC 失败回评审；不能默认以命令输出替代交互终端 |
| Q-023：回放存储 | 终端内存 1 MiB；落盘 7 天 / 每终端 10 MiB / 总量 100 MiB，先触发者轮转 | 有限历史，游标过旧明确提示缺失；不保留无限终端输出 |
| Q-024：Git 范围 | 基础结构化操作，pull 仅 ff-only / push 仅当前上游，L2 逐次批准；人工动作独立于 Turn | 不做 force / reset / clean / 删除分支 / 远端编辑，Git 认证沿用主机配置 |
| Q-025：重叠项目根 | 根相同或互为祖先视为同一冲突域；独立 workspace 同样纳入 | 不同 projectId 但共享目录不能并发写；须 PoC 验证协调算法 |
| 文件范围 | 已有 UTF-8 文本编辑，512 KiB 上限；冲突手工合并，关闭脏 Tab 需确认 | 不含文件创建 / 删除 / 重命名、二进制和大文件编辑；草稿不存 localStorage |
| 任务顺序与预估 | 保留原 ID，新增 M2-0 / M2-1b / M2-3b / M2-4b / M2-5b，一次一个 | 不并行启动多个子系统；预计 17–26 工作日，仅供范围讨论 |

Q-021 是本草案最影响使用体验的选择。若希望同项目多 PTY 与 Agent 同时写，需先明确是否接受将交互终端视为外部写者，或引入隔离工作区；这会改变当前并发保证，不能由实现自行决定。
