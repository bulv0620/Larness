# 实施计划

1. I0-1：移除 pino-roll 的文件数量限制；独立清理器按 mtime 判断保留期，在启动及每日运行，停止时清理定时器。
2. I0-2：读取文件配置作为初始化基线；初始化事务同时提交 app_meta.init_pending（目标配置）和初始化/审计记录，提交成功后才发布文件；未提交则旧文件不变，提交后发布失败则业务失败关闭，启动先恢复再加载最终配置。异常注入测试覆盖提交前后。
3. I0-3：repository 读取 secrets，启动校验密钥存在及每条记录可解密；不输出明文，不自动重置。
4. I0-4（ADR-025 补充）：移除密码输入/计算与原生依赖，保留历史哈希，新实例旧列为空兼容标记；IPC 可选补丁（ADR-026 撤回版本升级，保持 1），拒绝旧密码参数。提取可测试的初始化设置收集和运行会话循环；默认复用有效配置，高级网络设置；保存后重启只发生在初始化阶段，不中断已有业务任务。

不引入依赖；按任务逐次提交，不修改已冻结 ADR 原文。

5. I0-5：验收复查补充，先 await 启动清理再创建 pino worker；每日清理调度跳过重复首次执行，启动清理错误在 logger 就绪后记录。以启动顺序测试防止打开/删除同一旧文件的竞态。

6. I0-6：按 ADR-026 撤回协议 v2，同步当前契约/使用说明，保留旧 ADR 历史；先测试握手版本，再改常量。停止已确认本仓库实例，按路径清单删除本地数据，使用临时目录完成 check/build/smoke，确认默认目录没有被重建。
