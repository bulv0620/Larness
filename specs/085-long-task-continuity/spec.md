# 085 长任务连续执行

> 状态：`ready`（2026-11-19 人类确认按默认值实施）。本切片改变 [ADR-059](../../docs/adr/ADR-059-long-task-budget-and-continuation.md) 的默认行为，新决策见 [ADR-071](../../docs/adr/ADR-071-long-task-continuity.md)（accepted）。

## 1. 背景与问题

[ADR-059](../../docs/adr/ADR-059-long-task-budget-and-continuation.md) 把长任务的主约束从步数改为“花费为主、时长为兜底”，并引入自动接续。该决策解决了当时的成本失控和固定步数截断，但在“用户不关心成本、只要求长任务完成”的使用方式下，当前默认值落在正常长任务的执行区间内，变成了新的截断来源：

1. **`contextWindow × 30` 的 token 上限并不大。** 每一步都会重发完整历史，30 个窗口实际只够几十个满上下文步骤；工具输出多、反复读文件、跑测试的任务很容易在完成前撞线。该上限按 token 而非金额计算，缓存命中率高的便宜任务也会被截停。
2. **180 分钟是 Turn 总墙钟，不是卡死检测。** 大型 install / build / e2e 可能跑满 3 小时；到点直接 abort，且 `budgetCause=duration` 不自动接续。
3. **接续深度固定为 3。** 原始 Turn + 3 次接续后，即使任务远未完成也停止。
4. **80% 收尾提示会主动要求模型停止探索。** 该提示要求“finish the operation... Do not start new work”，模型通常会在还有大量工作时提前总结。
5. **上下文管理阈值偏保守。** 装配只用 `contextWindow × 0.8`，70% 触发摘要压缩，跨 Turn 历史只取最近 40 条 user/assistant 消息；长任务可能过早丢失早期事实。
6. **无事实的上下文触顶不会接续。** 纯推理等没有工具事实的长任务，`factsAreEmpty` 会阻止接续，直接停在上下文边界。

这些限制不是模型能力不足，而是任务级门禁设计把“无人值守成本保护”放在了“任务完成”之前。当前目标不同：**正常长任务不应因为预算、时长或接续次数被截断；只有物理边界、操作级超时和真正的无进展才应介入。**

## 2. 目标

- G-1：正常用户会话中的长任务不再因为任务级 token 上限、Turn 总墙钟或固定接续深度而终止。
- G-2：上下文窗口压力由自动“换页”处理：保存检查点、创建接续 Turn、继续执行，而不是以 `budget` 结束。
- G-3：保留操作级超时：单次模型请求、单条命令、锁等待和审批等待仍可失败，但失败只影响当前操作，任务可继续。
- G-4：保留取消、授权、项目锁、审批与审计；接续是完整的新 Turn，不绕过任何执行约束。
- G-5：正常换页在界面和终态语义上不是“预算耗尽”，用户看到的是连续任务。
- G-6：用无进展检测替代总预算：长时间没有模型输出、工具输出、文件变更或计划进展时暂停并询问，而不是按总时长或总 token 杀任务。
- G-7：长任务保留足够的历史与事实：上下文装配、压缩阈值和历史加载方式按长任务目标重新校准。
- G-8：继续记录 usage 与阶段耗时，用于展示和诊断，但不作为默认的停止门禁。

## 3. 非目标

- NG-1：不改变 Provider 的上下文窗口，不发送超过窗口的请求；物理上限仍然存在。
- NG-2：不删除单次模型请求超时、单条命令超时、锁等待、审批 TTL、取消与安全授权。
- NG-3：不引入金额预算、计费、第三方 tokenizer 或新的 Provider 依赖。
- NG-4：不改变工具权限、审批策略、项目锁、审计和秘密处理。
- NG-5：不改变定时任务的 `timeoutSeconds` 语义；Agent Job 仍按 Job 超时取消，不自动做用户会话式换页。
- NG-6：不重做时间线视觉；只调整状态文案、继续标记和诊断展示。
- NG-7：不把 `maxOutputTokens` 与任务级预算混为一谈；单条回答的输出截断单独处理。
- NG-8：不改变“一个 Turn 固定模型/凭据”的既有快照语义。
- NG-9：不新增 Turn 状态；无进展等待复用现有 `INTERRUPTED` / 恢复入口，若需要原地暂停/继续，另开切片。

## 4. 用户故事

- 作为执行大型重构的用户，我希望任务在超过旧 token 上限后仍继续，直到真正完成或我主动取消。
- 作为运行长时间构建/测试的用户，我希望 3 小时不是硬终止点；只有具体命令或请求卡死时才失败。
- 作为长任务跨越多个上下文窗口的用户，我希望系统自动换页并保留目标、计划、已改文件、失败验证和未完成步骤，而不是显示“预算耗尽”。
- 作为只做推理、不调用工具的用户，我希望上下文满时也能继续，而不是因为“没有事实”直接停止。
- 作为用户，我希望看到任务真的卡住时被询问或暂停，而不是被一个固定的总预算静默切断。
- 作为安全负责人，我希望接续仍走完整授权、锁、审批和审计，不因为“自动继续”获得额外权限。

## 5. 验收场景

### A1 超过旧 token 上限仍继续

```gherkin
Given 一个用户会话正在执行长任务
And 已累计消耗超过旧默认上限 contextWindow × 30
When 模型仍有未完成的工作且没有物理窗口错误
Then Turn 不以 terminalReason=budget 结束
And 任务继续执行
And usage 仍被记录，但不作为停止条件
```

### A2 上下文换页是正常路径

```gherkin
Given 当前 Turn 的上下文达到换页阈值
And 仍可写入检查点
When 系统准备下一次模型请求
Then 保存包含目标、计划、已改文件、失败验证和未完成步骤的检查点
And 创建带 resumedFromTurnId 的接续 Turn
And 发出 turn.continued 事件
And 原 Turn 的 terminalReason 为 continued
And 界面把接续轮合并为同一任务流
```

### A3 无工具事实的纯推理任务也能换页

```gherkin
Given 一个长任务没有产生工具调用或文件变更
When 上下文达到换页阈值
Then 系统仍使用最近消息与摘要创建接续 Turn
And 不因为 factsAreEmpty 直接终止
And 接续 Turn 保留原始目标与当前结论
```

### A4 命令或请求卡死只失败当前操作

```gherkin
Given 一条命令超过单条命令超时，或一次模型请求超过请求超时
When 超时触发
Then 只终止该命令或该请求
And 向模型返回可处理的失败/超时结果
And 当前任务可以继续执行后续步骤
And 不把整个任务标记为预算耗尽
```

### A5 无进展时暂停而不是杀任务

```gherkin
Given 任务连续一段时间没有模型输出、工具输出、文件变更或计划更新
When 无进展阈值触发
Then 任务以现有 INTERRUPTED / 恢复入口进入等待用户状态
And 界面说明“长时间没有进展”
And 用户可以继续、调整或取消
And 默认不自动终止整个任务
```

### A6 用户取消优先于换页

```gherkin
Given 一个 Turn 正在运行或准备换页
When 用户取消
Then 不再创建新的接续 Turn
And 原 Turn 以 cancelled 结束
And 取消事件与审计记录完整
```

### A7 接续不绕过安全边界

```gherkin
Given 接续 Turn 需要写文件、执行命令或访问受保护资源
When 它执行对应工具
Then 仍按当前会话策略进行授权
And 仍需项目锁与必要审批
And 审计记录接续来源与工具动作
And 不因自动接续提升权限或跳过审批
```

### A8 物理窗口无法容纳时诚实失败

```gherkin
Given 检查点或压缩后仍无法把请求放入模型上下文窗口
When 系统准备发送请求
Then 不发送超窗口请求
And 以明确的上下文错误结束或暂停
And 不进入无限换页重试
```

### A9 定时任务保持自身超时语义

```gherkin
Given 一个定时 Agent Job 配置了 timeoutSeconds
When Job 达到超时
Then 按既有 Job 语义取消
And 不自动创建用户会话式接续 Turn
And Job 结果仍标记为未完整完成
```

### A10 输出截断与任务预算分离

```gherkin
Given 模型因输出上限返回 finishReason=length
When Turn 结束
Then terminalReason 为 output_truncated
And 界面提示“输出被截断”
And 不把它归因于任务级 token/时长预算
```

### A11 正常换页的界面语义

```gherkin
Given 一个任务因上下文换页而创建接续 Turn
When 时间线渲染整个任务
Then 不显示“预算耗尽”
And 显示“自动继续”或等效的连续任务标记
And 用户可展开查看换页原因与检查点事实
```

## 6. 功能需求

| ID | 级别 | 需求 |
|---|---|---|
| R-1 | MUST | 默认关闭任务级累计 token 上限；显式配置的正数上限仍可作为诊断/实验开关。 |
| R-2 | MUST | 除 24h 紧急兜底外，不再把 Turn 总墙钟作为正常任务的停止条件；单次模型请求和单条命令保留独立超时。 |
| R-3 | MUST | 取消固定 3 次接续深度；接续次数由任务是否完成、用户取消或紧急兜底决定。 |
| R-4 | MUST | 删除或严格限制 80% 收尾提示，禁止在正常预算进度上要求模型停止探索。 |
| R-5 | MUST | 在可用输入窗口（输入窗口扣除输出预留）达到 85% 时自动换页，而不是等到硬触顶后以 `budgetCause=context` 终止。 |
| R-6 | MUST | 换页检查点至少包含：原始目标、计划、已改文件、已运行命令、失败验证、未完成步骤和资源 ID。 |
| R-7 | MUST | 无工具事实时仍允许换页；使用最近消息与摘要承接，不因 `factsAreEmpty` 直接停止。 |
| R-8 | MUST | 保留操作级超时；超时结果返回给模型，任务可继续。 |
| R-9 | MUST | 增加无进展检测；默认暂停/询问，不自动终止任务。 |
| R-10 | MUST | 接续执行完整的授权、锁、审批与审计流程，不得提升权限。 |
| R-11 | MUST | 永不发送超过模型上下文窗口的请求；换页失败时给出明确终态，不无限重试。 |
| R-12 | MUST | `terminalReason=budget` 只用于物理边界、紧急兜底或用户显式配置的预算；正常换页不得使用该终态。 |
| R-13 | MUST | Turn 起点装配预算保持 80%，摘要压缩阈值提高到 80%；装配预算必须低于 85% 换页阈值。 |
| R-14 | MUST | 跨 Turn 历史加载从固定 40 条改为按 token 预算动态决定。 |
| R-15 | SHOULD | 日志记录换页原因、上下文前后估算、携带事实数量、连续换页次数。 |
| R-16 | SHOULD | 保留 usage、缓存和阶段耗时统计；这些数据只用于展示与诊断。 |
| R-17 | MUST | 保留紧急兜底：24h / 1000 步；`maxToolCalls=0`；只防代码 bug，正常任务不触发。 |
| R-18 | MUST | 新增 `terminalReason=continued`，表示“当前片段结束、任务继续”；Job 与 UI 不得把它当作任务完成。 |

## 7. 接口与契约变更

- REST：无新增端点；Turn DTO 继续使用现有 `terminalReason` / `budgetCause` 字段。
- WebSocket：复用现有 `turn.continued` 与 `context.checkpoint` 事件；不新增事件类型，不要求旧客户端理解新字段。
- IPC：无变更。
- 配置：初版不新增用户配置，先用模块内默认值与测试覆盖；是否暴露 `agent.longTask`（换页阈值、无进展超时、紧急兜底）见 Q-054。若新增，必须更新 `packages/shared/src/config.ts` 与配置文档。
- 事件 / 错误码：正常换页不得产生 `budget` 终态；物理窗口失败和紧急兜底仍使用既有 `budget` / `context` 语义。若新增错误码，必须同步 `docs/contracts/rest-api.md`。
- 终端原因：正常换页新增 `TurnTerminalReason=continued`（Q-058 已确认）。它表示当前片段结束、任务继续，不代表任务完成。仅扩展文本联合类型，不需要数据库迁移；必须同步 `packages/shared/src/events.ts`、REST/WS 契约、Job 判定与 Web 文案。

## 8. 数据与迁移

- 新表 / 新列：无。
- 索引 / 约束：无。
- 迁移与回滚：复用 `turns.resumed_from_turn_id` 与现有检查点/摘要表，不新增 schema 版本。
- 保留与备份：沿用现有保留策略；本切片不改变清理默认值。

## 9. 安全、权限与审计

- 身份与授权：接续是同一会话的新 Turn，沿用当前会话身份、审批策略和模型快照。
- 审批级别：不降低、不跳过；需要审批的工具仍按当前策略处理。
- 秘密处理：换页事实不得包含 API Key、Token、Cookie、环境秘密或未脱敏命令输出。
- 审计事件：`turn.continued` 继续记录来源 Turn、深度与原因；工具动作按现有审计分级记录。
- 失败关闭：检查点写入失败、窗口无法容纳或授权失败时，不发送越界请求，不静默丢弃任务；以明确失败/暂停结束。

## 10. 失败、边界与恢复

| 场景 | 行为 | 用户可见信息 |
|---|---|---|
| 检查点写入失败 | 当前上下文仍可容纳时继续本 Turn；否则以明确上下文错误暂停/结束，不无限重试 | “上下文换页失败”及可重试入口 |
| 摘要调用失败 | 回退到最近消息 + 现有事实；仍无法容纳则按上一条处理 | “摘要不可用，已保留最近消息” |
| 单次模型请求超时 | 返回 Provider 超时错误，按有界重试处理；任务可继续 | 该步骤失败，任务未整体终止 |
| 单条命令超时 | 终止命令进程组，返回 `TIMED_OUT` 工具结果 | 命令超时，模型可调整 |
| 无进展 | 暂停/询问用户；不自动杀任务 | “长时间没有进展”及继续/取消 |
| 用户取消 | 立即取消，不创建接续 | 已停止 |
| 物理窗口仍无法容纳 | 不发送请求，明确结束或暂停 | 上下文无法容纳，可缩减输入后重试 |
| 紧急兜底触发 | 以 `budget` 结束并记录真实原因 | 明确说明是紧急兜底，不是普通任务预算 |
| 定时 Job 超时 | 按 Job 的 `timeoutSeconds` 取消，不自动换页 | Job 未完整完成 |

## 11. 可观测性

- 日志：`context rollover`（before/after tokens、threshold、facts、depth）、`stall detected`（无进展时长/维度）、`turn timing`、`turn wrap-up requested` 仅保留紧急路径。
- 指标 / 状态：换页次数、当前上下文比例、最近一次进展时间、操作超时次数、usage 与缓存命中。
- 诊断入口：Turn 详情展示终态原因；正常换页显示为连续任务标记，不显示预算耗尽。

## 12. 测试计划

- 单元：`resolveSpendCap` 默认关闭；换页阈值与上下文装配；无进展检测；历史 token 预算；终态原因映射。
- 集成：超过旧 30× 上限继续执行；上下文换页创建新 Turn 并携带事实；无事实纯推理换页；命令/请求超时只失败当前操作；用户取消；定时 Job 超时。
- 安全：接续仍需审批/锁/审计；换页事实不含秘密；越界请求被拒绝。
- E2E / 视觉：长任务时间线连续、无“预算耗尽”、显示自动继续标记；输出截断单独提示。
- 手动：真实 Provider 执行一个跨旧上限、跨上下文窗口的长任务，记录终态与恢复路径。
