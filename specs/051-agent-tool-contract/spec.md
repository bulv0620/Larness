# Agent 工具描述与执行契约

用户于 2026-11-06 直接要求修复审计发现并增加规格约束。M3-10 是 G3 后纠错，沿用 ADR-038、ADR-040、ADR-042、ADR-044 与已验收的 M2 Git 操作范围。

## 目标与范围

- 开发终端描述说明仓库脚本、项目相对工作目录、终端与服务状态的区别、按 Turn 策略授权。服务登记工具、参数说明和界面区分登记字段与实际监听地址，明确通配监听可登记。
- 模型上下文声明当前工作区类型及执行层使用的 Turn 审批策略。没有登记项目时，模型工具列表仅提供该工作区可用的能力。终端输入描述区分审计元数据与可见的 PTY 回显，保留现有脱敏。
- Git add/diff 按字面路径操作。明确列出的目录按 Git 目录语义处理。switch 只切换已存在的本地分支。push 只将当前分支提交推至已配置的上游分支，不使用强制更新、默认推送 refspec、额外标签或子模块推送。
- 无新工具、外部 API、数据列、迁移、依赖或权限范围。保留现有终端租约、登记鉴权、预览隔离、Git 锁、审批、审计、超时及主机 Git 认证。

## 持续约束

1. 工具名称、描述、模型收到的参数 schema、system prompt、对应用户提示和工具结果属于执行契约。修改能力、默认值、作用域、审批、生命周期或成功条件时，同一变更必须对照实际 handler、契约和当前 ADR，更新所有受影响的描述。

   M6-4（2026-11-11）起，工具结果先按内容值裁剪再序列化，超大结果附 `page: { truncated, omittedChars }`；`read_file` 额外返回 `offset` / `nextOffset` 支持续读。任何实现都不得对已序列化的 JSON 做字符截断。

   M6 收口后补充（2026-11-12）：`apply_patch` 在解析前规范化常见模型形状（代码围栏、`\n` 双重转义、缺失 `---/+++` 头、CRLF、前置说明文字），上下文匹配仍保持精确（fuzzFactor 0）；失败信息改为可定位的 `patch could not be parsed: missing @@ hunk header` 等，并在工具描述里写清格式要求。

   M6 收口补充（2026-11-12）：`run_command` 描述明确「参数对象是 strict，只接受 executable/args/cwd/timeoutMs，cwd 必须是项目内相对路径」；`git_status` 等只读 Git 工具明确「非 Git 仓库或缺少 Git 时返回 GIT_UNAVAILABLE，不要用同一调用重试」；`tool.failed` 事件补 `issues`（字段路径 + 校验消息，不含参数值，最多 5 条）；系统上下文增加「Git availability at Turn start」，`refresh_observations` 返回 `git: { detected, observedAt }`，Turn 起点探测结果与 `projects.git_detected` 不一致时回写该列（修复 `git init` 后侧栏永久显示 no git）。

   M6-8（2026-11-11）`search_code` 增加 `contextLines` / `glob` / `maxFiles`，结果新增 `scanBudgetExhausted`，用于缩小扫描范围并以上下文替代重复读文件。

   M6-5（2026-11-11）新增只读工具 `refresh_observations`（L0、无参数、不申请项目锁），用于在系统快照过时后读取当前临时服务 / 终端 / PM2 观察；系统上下文改为 Turn 起点快照，不再每步重写。
2. 模型上下文中的状态与策略使用执行层同一已解析数据。模型工具列表按工作区适用性生成，后端仍独立核验。不得从展示文案推断授权，不得把终端存活、服务登记或预览意图写成业务健康证明。
3. 每条影响操作范围或安全的承诺都要有执行层验收，覆盖合法输入和至少一个会扩大范围、越权或误报成功的反例。工具或 prompt 变更还要通过实际上下文组装验证模型收到的描述、schema 和作用域。禁止只核对源码常量或只用文本快照替代执行测试。
4. 新增或修改此类能力的 spec 必须列出上述验证和受影响表面。测试纳入常规检查。无法自动化的表面需在验收中记录可复核的检查与结果。

M4 当前按 [ADR-050](../../docs/adr/ADR-050-pm2-cli-deployment.md) 使用通用命令工具完成部署，系统上下文提供真实 PM2 环境与服务/项目关联。原 ADR-048 的资源、REST、事件和预览边界继续适用。专用正式服务模型工具与运维 Turn 入口已撤回，普通项目会话可以部署。实际上下文、命令策略与关系验证见 [命令上下文契约](../../docs/contracts/agent-command-context.md) 和 [M4 验收](../050-deploy/spec.md#验收场景)。

## 验收场景

| ID | Given | When | Then |
|---|---|---|---|
| C1 | 项目或默认工作区，Turn 已解析任一种审批策略 | 组装实际模型上下文 | 作用域与策略准确，默认工作区可读/控制已授权终端，项目专用工具不出现在其工具列表 |
| C2 | 仓库有不同工作目录的开发脚本或受管终端监听通配地址 | Agent 查看工具说明，人工打开登记表单，后端登记和转发 | 工具说明保留实际绑定并按项目脚本和 cwd 启动，登记参数仍限既有枚举，真实通配监听可登记和预览 |
| C3 | AI 通过租约输入文字且程序回显 | 读取终端输出与审计 | 输出按既有规则脱敏后可见，审计没有正文，工具说明区分两者 |
| C4 | 仓库含带字面通配字符的路径和同模式匹配的其他文件 | 执行 add/diff | 只操作明确传入的字面路径 |
| C5 | 分支只存在于远端跟踪引用 | 执行 switch | 返回 GIT_CONFLICT，当前分支与本地分支集合不变 |
| C6 | 上游分支已配置，仓库存在推送默认配置、强制 refspec 或分支分叉 | 执行 push | 快进时只更新上游分支，非快进失败，其他引用不变，审批与锁照常执行 |

## 失败与测试

Git 解析不到有效上游时返回 GIT_CONFLICT，拒绝非快进。无工作区授权、无终端租约、服务归属无法验证仍按原规则拒绝。定向运行 Agent 上下文、策略、终端、Git、真实服务/预览和服务窗口测试，然后执行 pnpm check、pnpm build 和涉及登记表单的 E2E。记录复现、红测、通过项和未验证项。

M4-R3 进一步统一既有服务生命周期契约：系统固定注入 development_preview/persistent_pm2 的 owner、ID、路径和退出行为；临时资源按真实项目查询，工具描述/schema/登记结果标明 temporary。无专用部署工具/新权限/新迁移，实际上下文与真实服务登记正反例纳入定向验收，见 [050 spec](../050-deploy/spec.md#m4-r3-系统服务生命周期契约)。
